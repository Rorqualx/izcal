# Izcal animation: frame

Written 20 October 2026 (phase 1 of the first-principles-spec method), by the synthesis author.

## The problem and who has it

Izcal needs its own animation engine. The ledger lists animation as a component with no spec (**G-13**: "Web Animations, CSS transitions and animations, owner of `hg-interp`"), blocking GR-M1, and reconciliation 2 counts its staffing nowhere ([RN2 Section 4]). Until it exists, the DOM spec fires transition and animation events from a placeholder module, `hg-anim-events`, due to be replaced (DM 6.7, DM-M2); the graphics spec writes `hg-interp` on the animation spec's behalf (GR 6.24, L2g); the style spec leaves two inputs undefined ("scroll-driven timelines" and "compositor-run animations", ST 6.10); the layout spec hands scroll-timeline ranges and view-transition geometry to "the future animation spec" (LY 6.10, 6.19). The owner's direction (19 October 2026, phase 2c brief): engine work is all ours; MIT only; another engine's source is never evidence; no shortcuts; staging only for correctness, security or measurement; riscv64 alongside x86-64 and arm64 from the start.

Scope (the brief's list):
- **Web Animations model**: timelines (document, scroll, view), animations and their playback state machine, animation effects and timing, the effect stack and composite order, keyframe effects, `getAnimations()`, events and promises, removal of replaced animations.
- **CSS Transitions and CSS Animations** on that model, with the style spec: before-change and after-change styles, `@starting-style`, `transition-behavior`, per-property animation types and interpolation (CSS Values 4, Transforms 2, Color 4, `@property`), additive and accumulate composition, the animation and transition cascade origins and the re-entry into style each frame.
- **Scroll-driven animations and view timelines** with LY-D13's scroll ownership and GR-D13's compositor.
- **View Transitions** 1 and 2: same-document and cross-document; capture, snapshots, the `::view-transition` pseudo-element tree, compositing; security of cross-document snapshots.
- **Compositor-driven animation**: GR-D13 limits the compositor to `transform` and `opacity` (with `filter` and `clip-path` re-rastered in the content GPU process); derive from first principles which property classes can run off the main thread deterministically.
- **`requestAnimationFrame` and frame timing**: HTML's update-the-rendering (DOM spec owns the steps; this spec owns "update animations and send events"), GR-D15's frame clock.
- **SMIL**: coordinate with the SVG spec (being written in parallel, ledger G-12) and decide which spec owns SMIL timing.
- **Determinism**: interpolation and timing arithmetic identical across x86-64, arm64 and riscv64 (`hg-math`, JS-D12).
- **Users**: `prefers-reduced-motion` and user controls; energy (FP budgets; hidden pages get no frames).
- **Recording and replay**: animation time as a recorded input; **observability**: DevTools animation inspection and timelines; agents' "settled" signal.

Not in scope: the paint and raster of animated values (graphics), layout of animated geometry (layout), the SVG element and attribute layer and SVG DOM `animVal` (SVG spec), animated image decoding (media; MD-D19 already times frames from the document timeline), canvas-drawn and WebGL animation (graphics; driven by rAF, which is in scope), media playback timelines (media), the shell's own motion (shell UI design; AX already requires the shell to drop animations under reduce-motion).

Who has the problem:
- **People browsing**: motion that is smooth, starts promptly, does not drain the battery, never runs for hidden pages, and stops or reduces when they ask (vestibular disorders, photosensitive epilepsy, attention). Animation is the most visible place where "jank" is felt.
- **Web developers**: "why didn't my transition fire?", "why does this animation stutter?", "which animation is winning?", "why is it not running off the main thread?", "why does it look different in another browser?", and flaky screenshot tests caused by animations.
- **Izcal's engineers and agents**: the model must be deterministic (B1, DET-1, JS-D15), identical across ISAs (JS-D12), memory-safe with no `unsafe`, cheap in memory (FP-11's per-node budget; animations live in side tables), and expose a settled signal agents and tests can wait on without heuristics.

## What Izcal's specs already decide or constrain

- **HGBA-2 2.3.2**: P1–P6 (P2 compatibility outranks P4 speed); **M-1** parts 1–4; I-1 (process per (site, container), origin under FP-D8); C-1 WPT floors; ANC-1 anchors.
- **HGBA-3**: **B1** deterministic substrate (virtual clock, recorded inputs), B2 typed IPC, B3 fork/join phases, **B4** data plane and mutation log, B5 incremental with from-scratch reference, B6 property trees, **B7** pixel-optional rendering, B8 semantic plane, B9 agent principal, B10 AI off by default; **DET-1** (hashes identical in 1,000 of 1,000 replays); PRIV-2 (fingerprinting measured).
- **Stage 1 design**: G1–G9 (G3 determinism, G5 `forbid(unsafe_code)`, G9 anchors); 3.3 phase purity; 5.1 vsync message (now GR's BeginFrame).
- **JS engine spec**: **JS-D15** (every timing-dependent decision is a recorded B1 input); **JS-D12** (cross-ISA identity: NaN canonicalization where bits become observable); `hg-math` (L2s, owned by JS): one implementation of the implementation-approximated math functions on every ISA, no FMA contraction.
- **Resource footprint**: FP-11 (≤ 512 B† per node for DOM + style + layout + paint; animation state in side tables, FP 6.3), FP-12 (derived stores discardable), **FP-D4** (hidden ⇒ frozen after 30 s†, rAF does not run), FP-17 (hidden means no wakeups), **FP-18** (≤ 1 wakeup/s† idle with a static page), FP-21 (vsync only while something changes), FP-22 (energy per corpus run), FP 6.13 (energy attribution per site and script).
- **Style spec**: cascade keys with eight origin-and-importance levels including animations and transitions (6.9); `calc()` and colour conversions through `hg-math`; computed-length type an IEEE binary type with no FMA (6.9); **6.10**: animation engine supplies per element at each flush the animation-origin and transition-origin declaration blocks at the timeline's current time; style supplies before-change and after-change styles, `@starting-style` and per-property interpolation types generated from property descriptions; style pass runs no script; events queued; environment snapshot (preferences included) per document per frame; **ST-D18** feature admission (WG resolution, WPT, two shipping engines or an Interop focus area); G19–G24.
- **Layout spec**: **LY-D13** (scroll offsets primary in `hg-scroll`, a sequence-numbered delta protocol with the compositor, both directions recorded; layout hands graphics scroll-timeline ranges); LY-D3 (1/64 px fixed-point geometry, no float after the boundary, G39); LY-D10 admission (holds `interpolate-size`/`calc-size()`); LY 6.19 (view transitions capture old and new geometry from the fragment store).
- **Graphics spec**: **GR-D13** (compositor animates `transform` and `opacity` only, and scroll-driven animations of them sampled from the same offset it draws; `filter` and `clip-path` animations whose geometry needs no layout re-raster in the content GPU process each BeginFrame; one integer interpolation `hg-interp` shared by compositor and main thread; style's f64 converted at the boundary); **GR-D15** (per-OS timing source, compositor as scheduler, demand-driven, frame records; throttling a function of visibility and intersection only; hidden documents get no rendering opportunities; rAF cadence follows the display, quantized timestamps, 60 Hz in the Hardened profile); GR 6.28 (compositor-eligible animation record: id, property, keyframes in `hg-interp`'s integer form, timing function, start time at "ready", timeline; compositor reports per-frame sample time and end; View Transitions over out-of-process frames captured by the compositor); **G61** (no floating point in `hg-interp` and other canonical crates); GR-D18 (cross-origin surfaces never feed page-controlled effects); GR-D23 (16† compositor-mutable nodes per document; View Transition snapshots on their own FP-14 line); GR-D25 (flash analysis in DevTools; reduce-motion interventions proposed to the shell); O9 (reduced-motion replays).
- **DOM spec**: DM-D1 scheduler (rendering class when due); the decision-point register (BeginFrame ticks recorded); update-the-rendering step table ("update animations and send events" → animation spec; "pending view-transition operations" → graphics with the animation spec); rAF timestamp from the BeginFrame tick; DM-D10 clocks (100 µs / 5 µs coarsening with seeded jitter); the settled signal ("no runnable task, timer, fetch, animation or worker message can change subtree S before time T"); `hg-anim-events` interim; Web Animations listed as owned by this spec (6.18); rules G90–G99.
- **Accessibility spec**: one preference record (`hg-ax-prefs`) with reduced motion; R0 exposure of media features at spec values only; under reduce-motion the engine disables smooth scrolling, pauses `marquee`, applies MD-D19; AX-42.
- **Media spec**: MD-D19 (animated images and muted looping videos show first frame with a play control under reduce-motion; frame timing from the document timeline on the substrate clock).
- **Admission**: ST-D18 and LY-D10's rule binds new CSS animation features.

## What success looks like (measurable)

Candidate target dimensions, to become AN- targets:
- **Correctness**: WPT `web-animations`, `css/css-transitions`, `css/css-animations`, `css/css-easing`, `scroll-animations`, `css/css-view-transitions`, `svg/animations`, `css/css-transforms` (interpolation parts), `css/css-color` (interpolation), `css/motion`, `css/css-properties-values-api` (animation parts) at floors of max(F, best shipping engine).
- **Determinism**: animation outputs (effect values, events, computed timing) bit-identical in 1,000 of 1,000 replays and across x86-64, arm64 and riscv64; main-thread and compositor values identical bit for bit for every frame.
- **Smoothness**: compositor-run animations hold frame rate while the main thread is blocked; start latency from trigger to first animated frame.
- **Energy**: zero frames for hidden pages and invisible animations; no main-thread wakeups for compositor-only animations between events; steps() animations request frames only at step changes.
- **Memory**: animation side tables within FP-11; View Transition snapshots within their FP-14 line.
- **Security**: no `unsafe`; no re-entrancy from event dispatch or promise resolution inside the model's update; bounded work under adversarial counts; cross-document snapshots never cross origins.
- **Users**: reduce-motion honoured by engine-level controls with a measured breakage rate.
- **Visibility**: every running animation explainable (which won, why not composited, why a transition did not start), scrubbable under replay.
