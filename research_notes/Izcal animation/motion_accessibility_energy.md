# Izcal animation: motion_accessibility_energy

Compiled 2026-10-20. Primary sources were preferred (papers, specifications, maintainers' posts, release notes, issue trackers, OS documentation). No source code of any browser, engine or other project was read or cited; issue-tracker entries were read for their prose discussion only, never for patches or commits.
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

Scope note: the accessibility spec (AX 6.11, AX-D18) already decides the OS-to-media-feature mapping, R0 exposure at specification values, and that under reduce-motion the engine disables smooth scrolling, pauses `marquee`, applies MD-D19 (animated images and muted looping video show a first frame with a play control) and the shell drops its own motion. This note does not repeat that design; it supplies the history, the population, the standards state of a **UA-level reduction of author animations** (which no spec yet covers), the breakage evidence, the energy evidence and the user-control evidence the animation spec needs. The session's shared web-search budget ran out part way through; the items left unverified are listed in Section 10.

**Implications:** Izcal should not cite 35% as "people harmed by animation"; it is a balance-test figure. The honest statement is that a large, ageing population has vestibular dysfunction and an unmeasured fraction is affected by screen motion, plus an attention population; the design target is "the user can make motion stop", not a percentage.

Izcal can implement a forced mode along these lines as a user setting, with its exact rules published and proposed to the CSSWG, while keeping the page-visible signal to the existing boolean (privacy, 5.5).

## 6. Breakage constraints

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 6.1 | CSS Animations 1: an animation with duration 0s "still occurs instantaneously. Specifically, **start and end events are fired**"; with 0s duration it is instantaneous for any iteration count, including infinite. Fill modes still apply. | 0 s | [CSS Animations 1 ED §4.2–4.4](https://drafts.csswg.org/css-animations-1/) | 2026 | High |
| 6.2 | Web Animations: a zero-duration animation repeating infinitely reports `currentIteration` = +Infinity; the model is defined for it, so zero duration is a valid target state, not an error. | ∞ | [Web Animations 1 ED §6.5](https://drafts.csswg.org/web-animations-1/) | 2026 | High |
| 6.3 | Pages depend on animation events to proceed: the widely copied author pattern shortens durations to near zero (e.g. 0.01 ms) **instead of `animation: none`** so that code listening for `animationend` still runs. `animation: none` cancels the animation and no end event fires. | — | [A11Y Project](https://www.a11yproject.com/posts/understanding-vestibular-disorders/); CSS Animations 1 (cancel semantics) | 2013 (updated) | Medium |
| 6.4 | Forced reduction can make content **invisible** (Chrome team research summarised in #5321), and fill-forward animations position content (5.5): any UA intervention must land on the animation's end state (or a keyframe), never on "no animation". | — | [#5321](https://github.com/w3c/csswg-drafts/issues/5321); [#7440](https://github.com/w3c/csswg-drafts/issues/7440) | 2022–2023 | High |
| 6.5 | Script-driven motion (rAF loops, canvas, WebGL) is outside any style-level intervention; a UA can only pause, throttle or freeze it, which changes timing script can observe. | — | [#7440](https://github.com/w3c/csswg-drafts/issues/7440) | 2023 | High |
| 6.6 | Zero duration breaks scroll-linked and timing-dependent sites; scroll-linked intermediate states may be needed to use the site; discrete interpolation keeps the author's positions without continuous movement. | — | [flackr/reduce-motion README (prose)](https://github.com/flackr/reduce-motion#readme) | 2023 | High |
| 6.7 | No crawl or published measurement of breakage rates for any forced-motion mode was found; the Chrome research in 6.4 is summarised, not published. | — | Search of CSSWG threads above | 2026 | Medium |

**Implications:** The safe transformation is one that preserves the event sequence and the end state: duration scaling (Android's model) and discrete keyframe stepping both do; removal does not. Infinite animations need a separate rule (pause at a keyframe), because scaling an infinite animation's duration to zero makes it "complete" instantly with iteration = ∞. Izcal must measure breakage itself on a corpus before shipping a forced mode as default.

## 11. Implications for Izcal: a first-principles motion control and energy policy

1. **Two inputs, one record.** The OS reduce-motion boolean (and Android's duration scale, Apple's separate image and flash settings) feed AX's `hg-ax-prefs`; Izcal adds a browser-level and per-site override (Firefox has the global one; nobody has per-site). The page sees only `prefers-reduced-motion` at its specification values (AX R0); internal scale values never reach content.
2. **Three graded user levels, not one switch**, matching the CSSWG direction (5.2–5.8) and UAAG 2.10.5: (a) **Reduce** (OS default when the preference is on): the media query matches; UA features (smooth scroll, `marquee`, MD-D19 images and muted looping video) per AX; view transitions use the CSSWG-resolved cross-fade without size or position animation (5.8); author animations are untouched. (b) **Reduce strongly** (user opt-in, global or per site): motion-inducing properties (WCAG's definition, 3.3–3.4: transform and its individual properties, offset/motion path, position and size properties, scroll-driven position) become **discrete between keyframes** with a minimum dwell (≥1 s†); colour, opacity and blur keep animating; animations marked safe (defined under the media query, or `motion: "reduced"` if specified) are exempt; events, promises, fill and end states unchanged. (c) **Stop motion now** (one shell command and keyboard shortcut, per page): every running animation, scroll-driven effect, animated image and muted looping video is paused at its current or nearest keyframe state; rAF continues (script-driven motion is outside UA control, 6.5) but the shell offers to also throttle rAF for that page with a visible indicator. Each level is documented exactly and proposed to the CSSWG as an implementation report for #7440.
3. **Never remove an animation; transform its timing.** Removal fires no end event and can leave content invisible (6.3, 6.4); discrete stepping and duration scaling keep the event sequence and the end state. Infinite animations are paused at a keyframe, not zero-durationed (6.2). This choice must be validated by a breakage corpus (forms, carousels, menus, scroll-linked sites) with a published breakage rate before level (b) becomes default for anyone (no published data exists, 6.7).
4. **Determinism and privacy.** The level is an input recorded with the document's timeline (B1); a page can detect level (b) or (c) by timing (5.5), which is why they are user opt-ins, never inferred, and why the only exposed signal stays the boolean.
5. **Energy rule: invisible animation costs zero.** An animation whose target is not painted (offscreen beyond a published margin, `visibility:hidden`, zero opacity of a composited layer, occluded, in a hidden or bfcache document) is not sampled, styled or painted; its timeline and events stay exact so the throttling is unobservable to Web Animations (8.1, 8.3), except where Contain 2 defines skipping (8.5). Firefox's 60% → 1% CPU case (7.4) is the regression test.
6. **Battery rule, published.** On battery saver (OS signal) or FP-D15's per-site limit, visible animation frame rate is capped at a published value (30 Hz†, the iOS precedent, 8.7); composited-only animations never wake the main thread between events; `steps()` and discrete animations request frames only at step changes (frame). Chrome and Edge do not publish their rules (8.9–8.10); Izcal states rates, triggers and exemptions and shows them in the FP intervention log.
7. **Measure what the literature lacks.** A per-platform energy table (idle, composited spinner, painting spinner, hidden spinner, offscreen spinner, animated GIF, looping muted video) as falsifiable targets, measured with OS power tools (7.1's method), e.g. hidden or offscreen spinner within 5%† of idle.
8. **Flash protection stays with GR-D25** (WCAG 2.3.1 analysis in the compositor); Apple's "Dim flashing lights" (2.6) is the only shipped precedent for automatic mitigation and is a reason to keep GR's proposed protective mode on the shell's list.
