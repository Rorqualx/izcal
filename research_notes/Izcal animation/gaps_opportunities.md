# Izcal animation: gaps_opportunities

Compiled 20 October 2026. Primary sources were preferred (specifications, survey reports, vendor documentation and release notes, issue trackers, Stack Exchange API data).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

**M-1 note.** No source code was opened, read or cited for this note: no code files, headers, commits, diffs or code reviews of any browser, engine, test tool, extension or library. Evidence is specification prose, survey pages, vendor documentation, release notes, bug-tracker summaries (title, status, dates), the Stack Exchange API, and documentation prose. Playwright facts come from its documentation; the CDP facts come from the published protocol reference (read as its published JSON protocol definition, the same artifact the DevTools spec's `hg-cdp` uses; no implementation code).

**Scope.** What developers and users struggle with in animation, what today's animation tools show and fail to show, how automation and tests cope with animation, and what Izcal could expose that no one does. Phases 2–3 of the first-principles-spec method; synthesis belongs to the spec author.

**Relation to the accepted specs.** The Izcal DevTools spec (revision 0.2) has no animation view: the word appears once, about Long Animation Frames. Its general machinery applies: recorded sessions (DT-D2), why-queries checked by counterfactuals (DT-D3), spec anchors, and the agent channel. Other specs already decide: compositor animations are limited to transform and opacity (graphics and rendering, ledger A-FUT-4); animated images pause under reduced motion with a per-image play control (images and media, MD-D19); reduced-motion replays are a graphics "O9" question; the DOM spec fires transition and animation events from style's before-change and after-change styles as a placeholder until this spec exists (ledger G-13). The gaps below are relative to those.

**Implications:** the evidence clusters into four questions developers cannot answer by looking: *why did this not animate* (1.11, 1.12, 1.16, 1.17), *which effect won* (1.13), *why is it slow or blurry* (1.6, 1.14) and *does it behave the same in other engines* (1.2, 1.7–1.10). The first two are answerable exactly by an engine that records each style change event's before-change and after-change styles and each property's effect stack; no tool does so today (Section 2).

## Open questions and black-box measurements needed

1. **Chrome's compositing-failure reasons.** The list is shown in the product but not documented (2.6). Record it black-box (trigger each known case and read the Summary tab) if Izcal wants CDP-compatible reason codes; Izcal's own reasons follow its own compositor rule regardless.
2. **Reduced-motion adoption by users.** No OS vendor or survey figure was found (4.5). Needed to size the motion audit and user control; a source to try is WebAIM's screen-reader and low-vision surveys.
3. **MDN Web DX / Web DNA ranking of animation.** The search budget ran out before the 2023–2025 MDN DX results were found; the 2020 report found does not single out animation.
4. **State of CSS per-feature usage** for view transitions, scroll-driven animations and `@starting-style` (percent used / heard of): the result pages render charts whose values were not in the fetched text.
5. **Primary usability evidence on parallax and scrolljacking** (NN/g's own articles) was not read; 4.13 is Low.
6. **How engines time style change events** relative to script reads and rAF (1.16) needs a black-box test matrix across Chrome, Firefox and Safari before Izcal fixes its own (and documents it as deterministic).
7. **Cost of decision records.** Size and write rate of per-style-change-event transition records and per-property effect stacks on animation-heavy pages; no outside data exists; prototype measurement.
8. **Whether `chrome.accessibilityFeatures.animationPolicy` works on desktop Chrome** (4.9) was not confirmed.
9. **Energy per animation in other browsers** has no published per-animation figure beyond the two anecdotes (4.11, 4.12); measure Izcal against Chrome and Safari on a fixed set of animation pages (spinner, marquee, parallax, idle cursor).
