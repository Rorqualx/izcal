# Izcal animation: independent design critique (phase 8)

Written 20 October 2026 by a reviewer who did not write the spec. Subject: `reports/Izcal animation.md`, draft 0.1 (788 lines; line numbers below refer to that draft). Method: `.claude/skills/first-principles-spec/SKILL.md`, phase 8, with `references/spec-template.md`. No source code of any project was opened for this review; only Izcal's own documents and the spec's research notes were read.

**Read against:** HGBA-2 2.3.3 (M-1 parts 1–4 with the 2.3.3 evidence rule and OD-7, P1–P6, I-1 and its shared-process exceptions); HGBA-3 (B1, B4, B7, B9, B10 with R0, DET-1, PRIV-2); Stage 1 design (2.2 G1–G9, 3.3 phase purity, D-S1 and its opt-in uniformity, S-4a Hardened profile); JavaScript engine 0.4 (JS-D12, JS-D15, 6.9 and 6.15 `hg-math` in L2s, JS-50, JS-52); resource footprint 0.4 (FP-1, FP-11, FP-12, FP-14, FP-18, FP-21, FP-D4, FP-D15, Sections 6.3, 6.4, 6.6, 6.8, 6.13, 6.14); HTML and CSS parsing and style (6.9, 6.10, 6.12, 6.15 crate table, ST-30, ST-33, ST-D18); layout 0.3 (LY-D3, LY-D10, LY-D13, 6.19); graphics and rendering 0.4.1 (GR-D3, GR-D5, GR-D13, GR-D15, GR-D18, GR-D23, GR-D25, G61, G63, GR-18, 6.1, 6.3, 6.4, 6.8, 6.9, 6.20, 6.21, 6.24, 6.28, 9.5); images and media 0.4 (MD-D19, MD-D20); DOM, bindings and event loop 0.2.1 (DM-D1, DM-D10, 6.7 register and rendering steps, 6.15 listener ledger and settled signal, 6.17, G90–G99); accessibility 0.2.1 (6.11 `hg-ax-prefs` and the R0 exposure policy, AX-42, 9.5 rows to GR and shell); DevTools 0.3 (DT-D2, DT-D3, G10–G12); reconciliation 2 (Q15, Q18, Q20, Section 4); Phase 3 ledger (G-12, G-13, A-FUT-1, A-FUT-4); and the in-progress **SVG spec** (`reports/Izcal SVG.md` draft 0.1: SV-D4, 6.9, G120–G129, 9.3, 9.5). The owner direction in the phase 2c brief is applied as binding.

**Phase artifacts.** Phase 1 (`frame.md`) and seven strand notes exist; Sections 1–11 follow the template; Appendix A is a placeholder. Phase 8 had not run; this is half of it.

**Overall.** The spine is right and well argued: one Web Animations core for every front end (AN-D1), an exact numeric contract with a stated far path (AN-D2), a walk that runs no script and returns a change list (G130), generational handles in a per-document arena (G131), broker-decided cross-document View Transitions with unreadable snapshots (AN-D7, G136, G137), published limits, graded motion controls that never remove an animation (AN-D10) and decision records for every implementation-defined choice. The weak points are where animation meets a component it does not own or a thread that runs beside the main one: the compositor's G63 boundary and its memory, the parallel style pass, the SVG spec written in parallel (which claims the same SMIL engine), the per-document time origins that the "one frame time" rule ignores, the R0 exposure rule, and an energy rule that would freeze animations that move content into view. Seven findings are High.

**Counts: 29 findings: 7 High, 14 Medium, 8 Low**, plus 6 engine-source and licence items (E1–E6) and 18 reconciliation items (R1–R18).

## Summary of the High findings

1. **C1:** Class C puts motion-path sampling over `hg-path` and a much larger record into the compositor, which G63 and GR-18 forbid; 9.5 does not amend them. Fix: split `hg-interp`, keep paths out of the compositor, review the record's growth.
2. **C2:** The SVG spec already owns `hg-smil` and asks for attribute effects, `accumulate`, child timelines and a priority key; this spec claims the same SMIL engine, writes `animVal` against SVG 2, and holds `iterationComposite` that SMIL needs. Fix: adopt SV-D4's split and extend the effect model.
3. **C3:** The offscreen skip stops sampling animations that move their own target into view, and its "unobservable" claim is false. Fix: visibility over swept bounds, exemptions, and a correct statement of what skipping changes.
4. **C4:** Transitions and animations are created, numbered and allocated inside the parallel style pass, which breaks phase purity, and the `hg-style`–`hg-anim` dependency is a cycle. Fix: a sequential post-pass and a trait boundary.
5. **C5:** Nothing bounds keyframe bytes a page can push into the shared compositor. Fix: per-record and per-key caps with demotion.
6. **C6:** "One F for every document" ignores per-document time origins (AN-54 fails by construction), and the unjittered F can exceed a jittered `performance.now()`. Fix: one absolute tick, per-document F, an ordering invariant, and worker rAF defined.
7. **C7:** Hiding reduced motion in the Hardened profile contradicts R0 and the accessibility spec's policy and silently changes MD-D19. Fix: follow AX 6.11; only the opt-in uniformity profile reports defaults.

## What the spec gets right (keep in revisions)

- **One timing core for every front end** (AN-D1), with the group-ready timing tree, so Level 2 is an admission decision rather than a rewrite.
- **The walk runs no script** and returns a change list (G130), with **generational handles** in a per-document arena (G131): a direct answer to the three in-the-wild animation exploits.
- **Exact time and exact boundaries** (AN-D2), with the double read-back rule and a stated fallback per part if AN-S1 fails.
- **The renderer resolves "ready"** from recorded frames, so no compositor timing enters the model (AN-D5).
- **The off-main-thread conditions (L), (P), (D)** written down, the group rule, the hand-off snapshot rule and **recorded demotions** instead of silent fallback.
- **Cross-document View Transition eligibility in the broker**, unreadable snapshots, and published limits (AN-D7, G136, G137).
- **Motion controls that change timing, never remove an animation**, with one exposed value and a measured breakage gate before anything is suggested (AN-D10, AN-70).
- **Frame demand from analytic next-change times** and per-animation votes, with targets that can fail (AN-30, AN-31, AN-35).
- **Decision records and why-queries** (A1–A8) for every implementation-defined choice, tagged "Izcal choice" with a filed issue (G135).
- **A clear M-1 section**, with every limit marked † and every value only source would state routed to a black-box question.
