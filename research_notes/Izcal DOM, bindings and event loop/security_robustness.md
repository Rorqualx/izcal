# Izcal DOM, bindings and event loop: security and robustness

Compiled 19 October 2026. Primary sources were preferred (vendor security pages and advisories, Project Zero and GTIG root-cause analyses, peer-reviewed papers read as PDFs, specifications, maintainers' blog posts, browser-compat-data).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, the researcher's classification of primary data, secondary coverage that quotes the primary, a vendor claim without data, or a well-known date not re-checked this session; **Low** = secondary source only, or the researcher's recollection not checked against a source this session.

M-1 note: no engine source code was read for this note. No code files, headers, commits, diffs, code-review pages or source browsers of Blink, Gecko, WebKit, V8, SpiderMonkey, JSC or any other engine were opened, and no patch link in any advisory or root-cause analysis was followed. Two kinds of prose page that were read quote engine code inline: the Project Zero blog post on CVE-2022-22620 and the 0-days In-the-Wild root-cause analyses (RCAs). Only their prose was used: bug class, trigger, timeline and stated lessons. No function name, type or constant from a quoted snippet is used here as evidence of how an engine is built. Chromium's security documents (`docs/security/*.md`) were read as rendered prose pages on chromium.googlesource.com. No code file in that repository was opened. Where this note says what an engine "does", it is evidence to reason from, not a shape to copy.

**Corrections after the phase 8 fact-check (20 October 2026):** Section 3's implications rest on three bugs, and 3.4 (CVE-2021-26411) is known from one sentence of Project Zero's 2021 review, not a full analysis; CVE-2021-1879's RCA classes it as a plugin script object not tracked by the garbage collector, with the mutation-event listener as the proof of concept's trigger. Row 7.6 (Minerva) cites the repository README only for the method description; no code file was opened, and the spec does not cite Minerva.

**Implications:** UAF is half of all memory-safety bugs, and the mitigations that work make the freed-and-reused state unreachable: GC (Oilpan, MemGC), quarantine (MiraclePtr) or types (Rust). MiraclePtr is explicitly *not* used in renderers, so Izcal's DOM, which by JS-D4 is traced together with JS objects with node columns released only by ID at event-loop points, must make "use after free" a type error rather than a quarantine. The Quantum CSS regression (1.10) shows that a memory-safe rewrite still needs the semantic checks carried over as tests.

**Implications:** Every in-the-wild DOM UAF read in full this session (3.1, 3.3, 3.4) needed author script to run in the middle of an engine algorithm (an event, a mutation event, a callback or a deserializer) and free something the algorithm still held. Izcal can design this out: DOM algorithms take no long-lived borrows across any point that can run script (events, `[CEReactions]`, conversions, serialization getters), and its IDL compiler can generate conversions-first, then-act bindings, with the "can run script" points typed and checked.

**Implications:** Navigation security is mostly about *who decides*. History entries, user activation, sandbox flags and the displayed origin must be decided in `hg-navigation` in the broker from IPC facts, never from renderer claims. Activation should be a capability the broker mints, as Chrome's "secure gesture" principle (5.5) implies.

## 11. Robustness: denial of service, hangs, depth and resource limits

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 11.1 | Chrome does not treat DoS as a security bug: "Denial of Service (DoS) issues are treated as abuse or stability issues". Sites "preventing you from leaving" are abuse reports. Reproducible CHECK crashes are welcome as bugs. | — | [Chrome Security FAQ](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/faq.md) | living doc | High |
| 11.2 | **Killing scripts** is allowed by HTML even though JavaScript does not account for it: "User agents may impose resource limitations on scripts, for example CPU quotas, memory limits, total execution time limits", and may then "throw a QuotaExceededError, abort the script without an exception, prompt the user, or throttle script execution". An abort empties the execution context stack "without triggering any of the normal mechanisms like finally blocks". | — | [HTML §8.1.4.5 Killing scripts](https://html.spec.whatwg.org/multipage/webappapis.html#killing-scripts) | living std | High |
| 11.3 | **Tree depth**: HTML parsing defines no maximum depth. All three engines' `DOMParser` flatten at 512 nested elements (black-box, 2024), and that divergence from other parsers caused a sanitizer bypass (6.2). Recursive DOM algorithms then face stack overflow, which Chrome classes as unexploitable DoS (1.13). | 512 | [Mizu 2024](https://mizu.re/post/exploring-the-dompurify-library-bypasses-and-fixes); [Chrome FAQ](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/faq.md) | 2024-11-17 | Medium |
| 11.4 | **Sync dialogs** (`alert`) block the event loop, and "User agents are encouraged to allow users to disable scripting whenever the user is prompted". Cross-origin iframe dialogs were the spoof vector in 10.7. | — | [HTML §8.1.4.5](https://html.spec.whatwg.org/multipage/webappapis.html#killing-scripts); [chromestatus 5148698084376576](https://chromestatus.com/feature/5148698084376576) | living std | High |
| 11.5 | Large URLs: Chrome caps at 2 MB to protect IPC from DoS, while "the web platform does not have limits on the length of URLs (although 2^31 is a common limit)". | 2 MB | [URL Display Guidelines](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/security/url_display_guidelines/url_display_guidelines.md) | living doc | High |
| 11.6 | The same Chromium memory-safety analysis notes that "a high proportion of our non-security stability bugs share the same types of root cause" as memory-safety bugs. Crashes and security bugs are one population. | — | [Chromium: Memory safety](https://www.chromium.org/Home/chromium-security/memory-safety/) | undated | High |

**Implications:** Robustness limits (depth, attribute counts, URL length, script time) are where engines silently diverge from the spec and from each other, and divergence is itself an attack surface (6.2). Izcal should name each limit, put it in one place with a spec anchor or a "spec silent" flag, make recursive algorithms iterative or depth-bounded, and enforce budgets with the scheduler (which can preempt at recorded decision points) rather than with ad-hoc watchdogs.

## Open questions

1. **Minerva (FSE 2022) numbers**: bug count, CVEs, and its comparison with Domato and FreeDom were not verified (the ACM page was blocked). Fetch the paper before the spec cites them.
2. **Google's "Trusted Types – mid 2021 report"**: the 130-services, zero-DOM-XSS figure comes only through Roth et al. (6.7). The primary report and any later Google figure (for example a DOM-XSS share of Google VRP reports before and after) need a direct read.
3. **Per-engine nesting limits beyond `DOMParser`**: whether the 512 flattening also applies to `innerHTML`, `document.write` and streaming parse, and what each engine does at extreme attribute counts, needs an Izcal black-box test on current Chrome, Firefox and Safari.
4. **Current timer resolution per engine as of October 2026** (Firefox's and Safari's values when not cross-origin isolated, and the jitter) should be measured black-box. The values in 8.8–8.9 are from 2018–2021 posts.
5. **Chrome's History Manipulation Intervention** (skipping history entries added without user activation): ship version and design were not read this session; only the HTML spec's history-action activation (10.4) was.
6. **Prototype pollution reaching DOM sinks**: no primary numbers were obtained ("Probe the Proto", USENIX Sec 2022, could not be fetched).
7. **Structured-clone and transfer CVEs** beyond CVE-2022-22620: no vendor advisory naming a serializer or transfer-detach bug was located without search. This needs a targeted pass over Chrome Releases, MFSA and Apple advisories.
8. **WebKit in-the-wild components**: 17 of 27 WebKit in-the-wild CVEs from 2019–2025 are "unspecified" in the sheet (2.4). The DOM share in WebKit cannot be estimated from public data.
9. **Slow-script dialog thresholds** per engine (Firefox's support article was not fetchable): measure black-box.
10. **Renderer-side UAF share in Chrome after Oilpan**: MiraclePtr data excludes renderers (1.6), and no published figure gives the UAF share of *Blink* bugs before and after Oilpan. Ask, or derive from public Chrome Releases bug titles.
11. **Re-entrancy via WebIDL conversions** (3.8): the spec mechanism is clear, but no CVE whose root cause is `valueOf` during a binding conversion was read this session.
