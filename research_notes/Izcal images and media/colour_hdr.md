# Izcal images and media: colour management, wide gamut and HDR

Compiled 19 October 2026. Primary sources were preferred (papers, specifications, maintainers' posts, release notes, issue trackers).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

**Method notes.**
- ICC.1:2022, the ICC embedding technical note, CSS Color 4 (CRD 9 October 2026), CSS Color HDR 1 (ED 8 October 2026), Media Queries 5, PNG Third Edition, WebGPU (CRD) and the HTML Standard (19 October 2026) were downloaded and searched locally; rows citing them are High.
- Chrome shipping milestones come from the Chrome Platform Status JSON (`chromestatus.com/api/v0/features`), read on 19 October 2026.
- The shared web search budget ran out partway through. Later items were checked by fetching known primary pages directly; what could not be checked is listed at the end.
- M-1: no browser, CMM or codec source code, commit or code review was opened or cited. Search results that pointed at Chromium, Skia or Android source files, Gerrit changes or Chromium code reviews were discarded unread. CMM projects (Little CMS, iccDEV) are cited only for website or README prose, licences and CVE text.

**Implications:** The v4 sRGB profile's "not changed" condition and the v2 profiles' "may not alter" terms are not MIT. They could pass as standards-body data under the M-1 exception, but Izcal has no need for them. Colour spaces are defined by published parameters (primaries, white point, transfer function in IEC 61966-2-1, BT.709/2020/2100, CSS Color 4), so **Izcal should build every built-in colour space from those parameters in code**, and when it must emit a profile (for example for encoders) it should generate its own small v2/v4 profile. It would ship no ICC-authored files. A legal check that bare parameters are not copyrightable is still needed (open question Q1).

**Implications:** The ICC parser belongs with the other hostile-input parsers. How strict to be is a measurement question: what share of real profiles a strict v4.4 validator rejects (Q3).

**Implications:** Colour identity is three different kinds of input: an ICC blob, CICP code points (AVIF, PNG, JPEG XL, video) and legacy chunks. Izcal should normalise all three into one internal colour-space descriptor before conversion, with PNG's precedence order as the rule, and should make CICP the first-class path for HDR (ICC cannot express every CICP encoding, 1.2).

A throughput target should be set against about 80 MPixel/s per core-group (12.3) and GPU shader cost, measured on Izcal's rigs.
