# Izcal images and media: media pipeline, web media APIs and audio

Compiled 19 October 2026. Primary sources were preferred (papers, specifications, maintainers' posts, release notes, issue trackers).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data, or prior knowledge not re-fetched this session; **Low** = secondary source only.

**Method notes.**
- The specifications were downloaded on 19 October 2026 and searched as text: WHATWG HTML (media, embedded content, URLs and fetching), W3C MSE 2, WebCodecs and its codec registry, Web Audio 1.1 (TR and editor's draft), Autoplay Policy Detection, Media Capabilities, EME, WebVTT, Audio Output Devices, Media Session, Picture-in-Picture, Document Picture-in-Picture, Media Capture and Streams, MediaStream Recording, video-rvfc and WebRTC Statistics. Quotes in rows marked High were checked in that text.

## 1. HTMLMediaElement: state machines and the timing they expose

## 14. Open questions and black-box measurements needed

1. **`timeupdate` cadence in shipping engines.** Measure the inter-event interval in Chrome, Firefox and Safari over 60 s of playback (and under main-thread load) to choose Izcal's fixed value inside 15–250 ms.
2. **Overlay energy.** No primary published number was found for video-overlay power savings (macOS CALayer, Windows MPO, Wayland subsurfaces). Measure package and wall power for the same 1080p and 4K video composited vs promoted to an overlay on each OS. A Chromium code review reports a figure for macOS overlays; it is not usable evidence (M-1) and is not repeated here.
3. **Software vs hardware AV1 decode power** on current laptops and phones at 1080p and 4K, using Izcal's own decoder and the OS decoder, with RAPL/powermetrics/Monsoon. Published work (11.6, 11.7) gives relative numbers only.
4. **Audio output latency per OS** as delivered to a browser-like client: CoreAudio default and minimum I/O buffer, WASAPI shared default vs IAudioClient3 minimum on common hardware, PipeWire with a browser client. Measure round-trip with a loopback.
5. **`outputLatency` and `baseLatency` values** reported by each engine on each OS (black-box), to choose Izcal's reporting quantisation for PRIV-2.
6. **Autoplay behaviour of Safari's inference engine**: no published thresholds; only black-box tests can characterise it.
7. **MEI threshold**: Chrome publishes the per-playback criteria (7 s, 200×140) but not the ratio or visit minimum; Izcal does not need it if it adopts a stateless rule (Section 7).
8. **NetEq thresholds**: the design doc gives no numeric limits for acceleration or expansion; Izcal designs its own and measures against ITU-T P.863 or similar.
9. **Resampler quality targets**: Izcal needs its own published test set (sweeps, tones, impulse, passband ripple, aliasing) because the best-known public comparison site was unreachable.
10. **Vulkan Video driver coverage** on Linux in 2026 (RADV, ANV, NVIDIA) for each codec; probe on the LAN rigs.
