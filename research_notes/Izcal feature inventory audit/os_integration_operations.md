# Izcal feature inventory audit: OS integration and operations

Compiled 24 October 2026. Primary sources were preferred (vendor documentation, OS developer documentation, release notes).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

**Scope.** This strand covers what a browser needs to reach users and keep running on their machines: packaging, signing, updates, data pushed to the client, diagnostics, enterprise management, OS service integration, platform targets, embedding and automation, localisation, legal duties and security operations. Web platform APIs and visible product features are other strands. Rows are coarse: one row per capability.

**How to read the table.**
- **[SB]** in the Item column marks a ship blocker. Without it, the browser cannot reach users, or a large class of users (enterprises, a whole OS, a whole jurisdiction) cannot run it.
- Shipped by uses: **Y** = ships it; **P** = partial, or on some OSes only; **N** = does not ship it; **OS** = the OS supplies it and the browser rides on it (mostly Safari); **n/a** = the browser does not run on that OS.
- Safari runs only on Apple OSes. Its packaging, updating, signing and most OS services come with macOS. Many rows read "OS" for Safari for that reason.
- **Method note.** Search budget was small. I read these pages in this session and checked the claims in their text: the Microsoft Edge browser policy reference, the Edge update policy reference, the Edge IE mode page, the WebView2 introduction, the Firefox policy-template documentation, the Chrome Enterprise release-channel page, Apple's alternative browser engine requirements, the W3C WebDriver BiDi draft, and the Chrome headless documentation. Those rows are marked High. Other rows cite the vendor or OS documentation page that holds the item. I named those pages from prior knowledge and did not re-read them in this session, so those rows are **Medium**. Rows backed only by press or forum reports are **Low**. Every source is prose documentation. No source code, headers, commits, diffs, code reviews or repository data files were opened or cited.
- **Licence note (Izcal's MIT-only rule).** Several data sets that browsers ship are not MIT. Examples: the Public Suffix List (MPL-2.0), Unicode CLDR and ICU data (the Unicode licence), Hunspell-format dictionaries (mixed licences), and the vendors' root store lists (vendor terms). Rows that hit this are tagged **(licence)**. A later step must decide which ones Izcal rebuilds itself.

- **Verification depth.** Only nine pages were read and checked this session (see the method note). Rows backed by them are High. Most rows are Medium because their pages were named from knowledge. A follow-up pass should open each Medium source and confirm the claim, prioritising rows marked [SB].
- **Chrome's policy list was not readable.** chromeenterprise.google/policies renders with script, and the fetch returned only navigation. Chrome policy names in this file (`ComponentUpdatesEnabled`, `AutoSelectCertificateForUrls`, `WebAppInstallForceList`, `RemoteDebuggingAllowed`, `ChromeVariations`, `MetricsReportingEnabled`, `BackgroundModeEnabled`, `DefaultBrowserSettingEnabled`, `HardwareAccelerationModeEnabled`, `DnsOverHttpsMode`) are from knowledge and need checking.
- **Counts not verified.** Locale counts per browser (PO-14.1), Extended Stable lengths (PO-3.6), Firefox CT enforcement version (PO-4.5) and Windows/Linux ARM64 build status (PO-11.2, PO-11.5) need primary checks.
- **Firefox PWA status (PO-12.2, PO-12.7)** is uncertain. Firefox's desktop web-app work changed several times in 2024–2026.
- **Age-assurance law (PO-15.7)** is moving fast and jurisdiction-specific. It needs a dedicated legal read.
- **Not covered here (other strands):** developer tools, extensions APIs, password-manager and autofill UX, PDF viewer, reader mode, translation UX, sync data model, search and omnibox, and all web platform APIs. These touch this strand only through their OS or service dependencies, noted above.
- **Not covered:** ChromeOS-specific management, Android/iOS enterprise (Android Enterprise managed configurations, iOS managed app config), and Windows Server/terminal-server specifics beyond PO-1.16.
- **Not covered:** business operations such as revenue (search deals are only noted in PO-15.13), customer support staffing and enterprise support contracts (SLAs), all of which enterprises ask about in procurement.
- **Licence collisions with the MIT-only rule** are flagged (PSL, CLDR/ICU, dictionaries, root lists). HSTS preload list and CT log list licence terms were not checked.
