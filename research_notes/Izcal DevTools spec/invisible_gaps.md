# Izcal DevTools spec: invisible gaps (what developers cannot see or do today, and what Izcal could expose)

Compiled 2026-10-17. Primary sources were preferred (papers, specifications, maintainers' posts, release notes, vendor documentation, issue trackers). No source files are cited (M-1).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

**Scope.** This is the phase 3 strand "invisible data and gaps" of the first-principles-spec method. Sections 1–15 give the evidence: developer pain first, then each area, with what tools show, what they do not, and why. Section 16 maps the gaps to Izcal capabilities (`references/izcal-capabilities.md`; HGBA-3 B1, B2, B4, B5, B8, B9; Stage 1 design Sections 3–6). The note ends with the **Gap map** and **Lessons for Izcal**.

**Method note.** The shared web-search budget ran out partway through the research. After that, the researchers read only primary URLs they already knew. Items that could not be verified are marked "unknown" or left out, and are listed in Section 17.

**Which gaps should stay closed (HGBA-2 P1).** DevTools acts for the user, in the user's own browser. Precise data shown there is not shown to web content.
- **Page-facing APIs keep their limits.** Cross-origin attribution in LoAF and Long Tasks (4.1, 4.2), `"masked"` bfcache reasons (5.7), 100 µs GPU timestamps (6.4), and cross-origin memory aggregation (7.1) stay as specified. Izcal shows the precise values only in its own tools.
- **Recordings hold page content and credentials.** Recording stays off by default and user-initiated per tab (Stage 1 design Section 3.4). Export strips cookies, tokens and form values by default (2.11, 2.12). Sharing a recording is an explicit act, and the redactions are listed.
- **Decrypted traffic and TLS keys** are never written to disk without an explicit developer setting. Key export is a deliberate act, like `SSLKEYLOGFILE`.
- **User state that sites must not learn** (installed extensions, prompt quieting, bounce-tracking history, the repair overlay) appears only in local tools, never through any page-visible API. Agents receive it only within their origin set (B9).
- **Cross-origin data in one view.** A DevTools frontend that shows several sites' data at once concentrates cross-site data in one process. That is the exposure behind CVE-2026-95301, where cross-origin accessibility data leaked to a compromised renderer (HGBA-3 B8). The `hg-devtools` frontend therefore needs its own process and per-target capabilities, not a renderer that holds all origins.

## Lessons for Izcal

| Project | What happened | The lesson | How Izcal applies it |
|---|---|---|---|
| Firefox Web Replay | Bolted onto Gecko. Never covered media or WebRTC. Removed the day after its sole author's layoff (15.9) | Replay outside the core rots, and a one-person feature dies with that person | B1 is the substrate the engine's own CI runs on (DST), so replay cannot rot silently. GPU and media are declared out of scope rather than half-supported |
| Replay.io | Working technology, four product pivots in two years (15.11) | Replay as a separate product struggled to find a business. Its value showed up in bug reports and agents | Replay ships as a built-in DevTools feature, not a separate product. Recordings double as bug reports and agent context (16.14) |
| rr, Microsoft TTD | Hardware-counter dependence, single-threaded recording, 10–20× overhead (15.12) | Whole-process recording at the OS boundary is costly and platform-bound | Record at Izcal's own interfaces (clock, entropy, IPC, network), where the inputs are few and typed. DET-2 bounds the cost at ≤1%† |
| Timelapse (UIST 2013) | Deterministic replay, yet users were not clearly faster (15.14) | Replay alone does not help. The questions over the recording do | Build the queries (16.2–16.4) and spec explanations (16.5), not only a scrubber |
| Firefox Inactive CSS, bfcache reasons, speculation reasons | Each explains "why" for one feature (5.6–5.8) | Developers value cause explanations. Writing each one by hand does not scale | Derive explanations from the mutation log, the reference path and spec anchors, so every anchored algorithm can explain itself |
| Chrome Layers panel; Firefox Shader and Canvas editors | Low usage, then deprecation or removal (6.2, 15.15) | Specialised views of internals lose users when they show state, not causes. Usage data was never published | Show causes on the page (overlays) and in task-shaped answers. Gather opt-in usage data and publish it |
| Chrome Performance panel | The vendor called it "challenging" and dense, then merged panels and added AI insights (1.7, 15.15) | Density without a question to answer fails both newcomers and experts | Start from a question ("why was this interaction slow?") and disclose raw data progressively |
| LoAF and Long Tasks | Attribution withheld across origins and for workers (4.1, 4.2) | Page-facing APIs must hide cross-origin facts. That does not bind the user's own tools | Keep the spec's masking on page APIs. Show full attribution in `hg-devtools`, which acts for the user |
| Okta HAR breach | Session tokens in shared HAR files led to hijacked sessions (2.11) | Rich exports are credential leaks | Redact by default. List what was redacted. Make sharing a recording an explicit act |
| Selector stats and async stacks marked "(slow)" | Probes are off by default because of overhead (5.2, 4.9) | Observing in real time perturbs what is observed | Run the expensive probes on a replay under virtual time, where they cannot change the page's behavior |
| EventRacer and WebRacer | Found real harmful races but never shipped in DevTools. Too many false positives (15.7) | Race reports need a way to confirm them | Confirm a reported race by replaying both orders under the seeded scheduler (16.2) |
| Survey data on pain | Developers name symptoms (grid, sizing, flakiness), rarely "debugging" (1.1–1.3) | Tools should match symptom-shaped questions | Organise the tools around questions about elements, interactions and tests, not around engine subsystems |
