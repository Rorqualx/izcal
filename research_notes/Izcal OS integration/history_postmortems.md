# Izcal OS integration: history and postmortems

Compiled 24 October 2026. Primary sources were preferred (Microsoft Learn, the Windows and Windows Insider blogs, freedesktop.org and Wayland protocol specifications, the W3C Web Share Recommendation, Mozilla security advisories, Mozilla and Microsoft support pages, Bugzilla discussion prose, security researchers' own write-ups). No browser, library, tool or OS source file, header, commit, diff or code review was read: Chromium and xdg-utils source, searchfox and GitHub code views were not opened, even where a search result offered them.
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, a vendor claim without data, a contemporaneous expert blog, or a source read only through a summary; **Low** = secondary source only, or the researcher's recollection not checked against a source this session.

M-1 note: this file records ideas, dates, measurements and reasons. It contains no code and no design template from any stack. Where it says what an OS or browser "does", that is evidence to reason from, not a shape to copy. One prose page hosted beside code was used: Mozilla's rendered `firefox-source-docs.mozilla.org` page on setting the default browser on Windows. Under OD-7: no code file, header, diff or review was opened; no outside copy of that prose exists; no constant was taken from it, only the order and reasons of Microsoft's changes.

Method notes: the web-search budget went first to the Windows default-browser chronology (question 1), then single-instance models (4) and security incidents (8). Microsoft Learn pages were read in full, including their `ms.date`/`updated_at` metadata. Questions 5–7 (share, taskbar, media) got one or two searches each; rows there are often Medium or Low, and the gaps are listed under **Open questions**.

**Implications:** On Windows the only reliable, supported way to become the default is to **ask through Windows' own UI**: register complete Capabilities (http, https, .htm, .html and, for the EEA, the wider list including .pdf only if Izcal really handles it), send the association-changed notification once, and offer a deep link to Settings. Izcal must never write UserChoice: it is tamper-protected by a kernel driver, it is against Store policy, and silently claiming defaults is exactly what the protection exists to stop. Default status should be read-only (`QueryCurrentDefault`) and re-checked after OS upgrades and backup restores, because Windows itself is the most common thing that resets it. Surfaces that use `microsoft-edge:` are outside any browser's reach outside the EEA, so the spec must not promise "all links open in Izcal".

**Implications:** On Linux, Izcal should register through a Desktop Entry with `MimeType` (including `x-scheme-handler/http(s)`), be `DBusActivatable` so second launches become an `Open` call carrying an activation token, and write defaults only to the user `mimeapps.list` and only when the user asks. Every portal call needs a short timeout and a fallback, so a missing backend never blocks startup. Feature-detect portal versions instead of assuming them.

| 4.7 | **Wayland's `xdg-activation-v1`.** The launcher gets a token from the compositor and passes it by `XDG_ACTIVATION_TOKEN` (to be unset after reading) or by `activation-token` platform data. | 4.8 | **Firefox on Wayland uses D-Bus remoting** instead of X properties. Recollection, not checked. | — | (recollection) | ~2020 | Low |

**Implications:** Single instance should be a **per-profile IPC endpoint** (named pipe or AF_UNIX socket in the profile, or D-Bus `org.freedesktop.Application` on Linux, Apple Events on macOS), not a lock file alone. The hand-off must carry a version, the profile ID and an OS activation/focus token. A launcher that finds a different-version instance must refuse or open a separate profile, never hand URLs across versions. The lock must detect staleness (host and PID, liveness check) and say plainly which machine holds it.

**Implications:** These incidents are why the spec must treat every OS-integration edge as **untrusted input in both directions**. (b) Outbound: launching an external handler goes through the broker with a scheme allowlist, a per-origin, revocable grant, a user gesture, a top-level-navigation requirement, rate limiting, and **no observable difference** to the page between "handler exists", "handler missing" and "user declined", to close scheme flooding. (c) `file://`, UNC and share-mount schemes are never passed to the OS opener from web content. (d) Because apps will build bypasses when prompts are annoying, the grant UX must make legitimate repeat launches cheap.

## 10. What survived, and why

| # | Finding | Source |
|---|---|---|
| 10.1 | **Defaults are a user decision made in OS UI.** Windows (2012 → UCPD 2024 → Learn 2026-09), macOS (2014 prompt → all UTIs 2026) and freedesktop (user `mimeapps.list`) all converged on this. Programmatic silent setting lost everywhere. | §§1–3 |

| 10.3 | **Message the running instance, don't fight over a lock.** DDE and X properties died; command-line forwarding, D-Bus `org.freedesktop.Application` and Apple Events survived, and Wayland added an explicit activation token. | §4 |
