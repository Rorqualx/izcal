**Owner direction applied as binding:** engine work is all Izcal's; OS graphics APIs and drivers are interfaces; the Vulkan loader classified honestly; everything shipped available under MIT; no shortcuts for time or complexity, staging only for correctness, security or measurement; cost is a planning fact; the GPU processes and shader compilers designed for security first; another engine's source is never evidence; accepted decisions hold (JS, FP, ST, TX, NW, and the owner-signed Stage 1 decisions such as D-S1); this spec's rules start at G60.

**Phase artifacts.** Phase 1 (`frame.md`) is complete and accurate. Phases 2–3 are in eight notes plus Sections 2–3; phases 4–7 are present (Sections 4–11). Phase 8 had not run; this critique is half of it.

**Overall.** The draft is ambitious and mostly well argued. Two decisions are genuinely new and defensible: per-(site, container) content GPU processes (GR-D2) and canonical integer pixels (GR-D3). Direct DXIL, SPIR-V and MSL emission (GR-D7) is a third. The weak points are where those decisions meet things the draft does not model:
- **Cross-process GPU sharing.** Shared fences and shared tile textures cross the new process boundary, and a compromised content process can hang or deface through them.
- **The shared compositor** is still a single cross-site, trusted-UI and timing chokepoint.
- **Hardware hang semantics.** TDR resets the whole adapter, so the per-site split does not contain hangs.
- **Pixels the canonical rule does not cover.** Screen composition, WebGL output laundered into 2D canvases, and compute-shader output all escape it.
- **Accepted specs it contradicts.** I-6 on high-resolution timers, FP-7/FP-D8 on isolation as a memory lever, the security scope's CON-R rules, HGBA-2 5.3 on blocking readback, and the media spec 0.2's process and colour contracts.

Several reversal triggers are already tripped by the draft's own numbers.

**Counts:** 41 findings: **11 High, 19 Medium, 11 Low**. In addition there are 8 engine-source and licence items (E1–E8) and 24 reconciliation items (R1–R24).

| **C1** | **High** | **Shared tile textures and cross-process fences give a compromised content GPU process a way to hang the shared compositor and to write into another site's pixels.** The compositor allocates tile textures, "grants" them to content processes, and samples them after "a fence" per tile; "timeline fences shared across processes for tile handoff" are a HAL primitive. Problems: (1) an OS shared handle (NT handle, IOSurface port, dmabuf fd, `MTLSharedEventHandle`) cannot be revoked once duplicated, so if the compositor's pool ever re-grants a texture to another (site, container), the old holder keeps write access and can overwrite or read that site's tiles. "Pools zero on reuse" (G64) addresses reading, not writing. (2) A shared timeline fence or semaphore can be signalled by its holder to any value. If the compositor makes a **GPU-side** wait on it, a fence that never signals stalls the compositor's queue until TDR or Metal timeout, which loses the compositor device for every site. A fence driven to `u64::MAX` breaks all later waits on a shared fence. (3) Fences are mutable shared state, which IPC-R7's exemption ("opaque pixel and sample buffers that are only sampled") does not cover. | 6.0 (diagram, lines 182–184), 6.1 (line 215), 6.2 (line 225), 6.7 (line 302), G64 | IPC-R7, IPC-R8 (never reuse), IPC-R17 (no process trusts another) [SS 6.6]; HGBA-2 5.3 ("no HAL call blocks ... the compositor thread"); R-2 | Add **G71**: "A shared texture or memory object is granted to exactly one (site, container) for its lifetime and is never re-granted; it is freed only when that process exits or the compositor drops its own reference, and its bytes stay on that site's ledger until then (a holder pinning memory is charged and killed at its budget)." Add **G72**: "The compositor never makes a GPU-side wait on a fence another process can signal; it observes foreign fences on the CPU with a deadline (the frame deadline) and samples a tile only after its fence completed in time, otherwise it draws the last completed tile; one fence object per (content process, compositor) pair, never shared across pairs." Add both to the security scope as GPU-R14/GPU-R15 and to the adversarial-peer harness (IPC-R17: a content process that never signals, signals to `u64::MAX`, and keeps writing after release). Add a GR-11 case. |

| **C3** | **High** | **Hang isolation and recovery do not hold as designed.** Five problems. (1) The per-content-process watchdog stops a submission at **2 s† of GPU time, "under Windows' 2 s TDR"**. That is equal to TdrDelay, not under it, so TDR fires first. (2) On most WDDM drivers a TDR resets the adapter, losing **every** process's device, the compositor's included. One hostile page can therefore cost every site its device, and after three compositor losses in ten minutes force **browser-wide** CPU compositing (6.18). That is a cross-site denial of service the per-site split was meant to prevent; the same holds for Metal hang accounting if `accessRevoked` is per device or per system (Q-GR-11 is open). (3) Who counts toward HGBA-2 5.5's "three losses within ten minutes blocklists the class" is undefined. If a content process's reported losses count, any site can blocklist the GPU for everyone. (4) After acknowledgement the renderer keeps **only chunk hashes** (6.3, FP 6.4) and the display items live in the content GPU process. When that process crashes, nothing "re-rasters from retained display lists", although HGBA-2 5.5 and R-2 say exactly that. The renderer must re-run paint, and no message or target covers it. ## Engine-source and licence items

- **E1. DXIL validator hash.** GA 3.2 grades the "modified MD5" Medium, "algorithm details read only as summary". The algorithm was "open-sourced in DXC v1.8.2502", which is source code of an excluded engine-work library (the frame lists DXC as one), so it can never be evidence (M-1 part 3). The spec's "computed from its published algorithm" holds only if INF-0004's prose specifies every modification. **Fix:** quote the exact prose in the note. If it is incomplete, derive the hash black-box with `dxil.dll` as a test-only oracle (inputs and outputs only), and record that as an observation.
- **E2. DXBC fallback.** GA 3.14 (Low): DXBC's token format is "published only as a WDK header", and its checksum is "recollection". The spec's "from Microsoft's published format and checksum" is a guess presented as fact. The public descriptions of the DXBC checksum are in open-source reimplementations (Wine, vkd3d, Mesa), which M-1 part 3 forbids. The WDK header itself is an OS-interface header and is fine to read for the token layout. **Fix:** mark the claim unverified; plan black-box derivation with `d3dcompiler_47.dll` as a test-only oracle, or drop DXBC and treat a failing vendor as WebGPU-unavailable there.
- **E3. DXIL container parts.** GA 3.5: `DXIL.rst` describes "the container parts ... less completely". Anything missing must not be filled from DXC source. **Fix:** list the container fields the emitter needs, map each to a prose source or a black-box observation (dumping `dxc` output as a test-only oracle), and flag gaps in 11.2.
- **E4. Listener timeout values.** The 400 ms† desktop and 600 ms† mobile non-passive-listener timeout is "matching the published precedent", i.e. Firefox's APZ documentation (CS 4.4). Taking another engine's constant from its documentation is a template, not evidence. The behaviour is web-observable and spec-silent, so M-1 part 2 asks for a three-engine black-box observation. **Fix:** set the value from first principles, for example from the human-perception and input-latency targets, or record a black-box observation of all three engines (Q-GR-3's method), and file the gap with the UI Events or Pointer Events editors.
- **E5. Chromium documentation hosted in the source tree.** The notes link `chromium.googlesource.com/chromium/src/+/HEAD/docs/` Markdown (`how_cc_works.md`, `life_of_a_frame.md`, `design/sandbox.md`). They are prose, earlier specs use them, and Section 7 says so. M-1's text names "code files"; these are files in the code repository. **Fix:** record once, in the Stage 1 decision log, that Markdown design documents in an engine repository count as prose, or cite the chromium.org copies where they exist.
- **E6. WebKit Bugzilla links (7).** Bug-tracker discussion is allowed prose, but those pages carry patch attachments (diffs). **Fix:** state in each note row that only the comments were read, and add a check that no cited bug page was used for an attachment.
- **E7. SPIR-V grammar licence.** "MIT with Khronos's notice" is a modified MIT text, not MIT; its generated tables ship in Izcal binaries. It fits M-1's "standards data published by the standards bodies themselves" exception better than "MIT". **Fix:** classify it under the standards-data exception in Section 7 and the licence audit, keep the notice, and do the same for any Vulkan header text the generator embeds (`vk.xml` is Apache-2.0 OR MIT, so the MIT choice applies there).
- **E8. Binding-crate licences and the loader.** The `objc2-*`, `dispatch2` and `windows-*` licences are stated "crates.io, 19 October 2026"; `deny.toml` must confirm each version, and `objc2`'s transitive crates must too. The Vulkan loader classification is honest and conditional (G67). The licence audit's class-5 row lists the "Renderer" as a graphics-API user, which contradicts I-2 (R22). **Fix:** run `cargo deny` on a prototype manifest at GR-M0 and record the result; amend the audit row.
