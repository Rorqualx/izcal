# Izcal graphics and rendering: gaps and opportunities

Compiled 19 October 2026. Primary sources were preferred (specifications, survey result pages, vendor documentation and release notes, engine teams' blog posts and wiki prose, papers).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, secondary coverage that quotes the primary, a vendor claim without data, or a page fetched only in part; **Low** = secondary source only, or the researcher's recollection not checked this session.

M-1 note: no engine source code was read for this note. No code files, headers, commits, diffs, code-review pages or source browsers of Chromium, Skia, Dawn, ANGLE, Gecko, WebRender, wgpu, WebKit, Servo, Ladybird, Vello, Flutter/Impeller or any other engine were opened. Search results that pointed to Chromium's `gpu/config` directory on googlesource, a Chromium code review about screen-magnifier caret tracking and Skia's Git mirror of Vello were not opened or used (see "Sources not used"). Where a value exists only in source (for example the number of Chrome's GPU driver workarounds), it is recorded as an open question for a black-box measurement. Licence files (RenderDoc, Perfetto) were read only to classify licences.

Graphics developers (canvas, WebGL, WebGPU) are absent from the big surveys, so Izcal needs its own evidence channel for them (issue trackers, CTS failures, its own telemetry under consent).

Izcal should show them to DevTools and agents under consent through IIP, never to pages, and keep page-visible timings at the coarsened values the specs set.
