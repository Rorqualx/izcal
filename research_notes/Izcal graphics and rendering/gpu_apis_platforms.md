# Izcal graphics and rendering: GPU APIs and platforms as OS interfaces

Compiled 19 October 2026. Primary sources were preferred (Khronos registries and LICENSE files, Microsoft Learn and DirectX developer blog posts and specs, Apple developer documentation and the PDFs Apple publishes, crates.io licence fields, Google's Android dashboards).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, secondary coverage that quotes the primary, a vendor claim without data, or a well-known fact not re-checked this session; **Low** = secondary source only, or the researcher's recollection not checked against a source this session.

M-1 note: no engine source code was read for this note. No code files, headers, commits, diffs, code-review pages or source browsers of Chromium, Dawn, ANGLE, Tint, Skia, Gecko, WebRender, wgpu, naga, WebKit, Mesa, SwiftShader or any other graphics engine were opened. LICENSE files, crates.io metadata, the Agility SDK NuGet package's licence and "distributable files" text files, Khronos registry *data files'* licence headers (`vk.xml`, `spirv.core.grammar.json`), and prose design documents (the Vulkan loader's `docs/*.md`, Microsoft's `DXIL.rst`, the HLSL proposal INF-0004 as summarised prose) were read. No Agility SDK header was opened. Where this note says what an API or a library "does", it is evidence to reason from, not a shape to copy.

**Method notes**
- 10 web searches were used. Everything else was fetched directly: crates.io's API (licence field of the newest version, 19 October 2026), raw LICENSE files on GitHub, Apple's documentation JSON and the two PDFs Apple publishes (Metal Shading Language Specification 4.1 dated 2026-06-04, Metal Feature Set Tables dated 21 May 2026), Microsoft Learn, the DirectX developer blog, Khronos's refpages (`docs.vulkan.org`), Mesa's prose driver docs, Android's distribution dashboard and the Steam survey.
- Crate licences are the crates.io `license` field of the newest published version; the repository LICENSE files of the crates were not opened one by one. Graded High for the field, but the open question at the end asks for a `cargo deny` audit of the whole dependency tree, since a crate's transitive dependencies can carry other licences.
- No licence text was interpreted as legal advice. Where a licence is not MIT and not an MIT-offering dual licence, the note says so and classifies it; the owner decides.

| **CPU reference raster** (all) | Any | n/a | Izcal (Rust) | Izcal's own code, MIT |
| **WARP** (Windows software D3D12) | In-box Windows | DXIL / DXBC | Microsoft's WARP JIT on the CPU (OS interface) | Nothing shipped |

**Implications:** every API Izcal needs can be reached with nothing shipped except MIT-licensed bindings and Izcal's own code, provided Izcal (a) loads the Vulkan loader from the system, (b) uses only the in-box D3D12 runtime and never redistributes `D3D12Core.dll`, and (c) writes its own DXIL, SPIR-V and MSL emitters. The cost is that D3D12 features that arrive only through the Agility SDK are out of reach until they are in-box.

**Implications:** all three APIs give per-pass GPU timestamps with CPU-clock correlation, enough for Izcal's per-frame timelines; GPU-side timing is not web-observable unless WebGPU timestamp queries expose it, where GPU-R7's coarsening applies.

## Open questions (to measure black-box or decide)

1. **Does the in-box D3D12 runtime accept the BYPASS hash?** Call `CheckFeatureSupport(D3D12_FEATURE_BYTECODE_BYPASS_HASH_SUPPORTED)` on Windows 10 22H2 and Windows 11 24H2/25H2 in-box (no Agility SDK). If not, Izcal must ship its own modified-MD5 hash (row 3.2).
2. **In-box D3D12 feature ceiling**: highest shader model (`D3D12_FEATURE_SHADER_MODEL`), enhanced barriers, `OPTIONS12+` on Windows 10 22H2 and Windows 11 24H2 for Intel, AMD, NVIDIA and Qualcomm reference machines. This defines Izcal's D3D12 tier, because the Agility SDK cannot be shipped.
3. **Does a self-produced DXIL container with a correct hash load and run** on all four IHV drivers without `dxil.dll` ever being present? Test with a minimal compute shader emitted by Izcal's own writer.
4. **Vulkan loader in the GPU sandbox**: which files the loader opens on Linux and Windows, which implicit layers load on typical machines (Steam overlay, OBS, MangoHud, device-select), and whether disabling implicit layers breaks PRIME/Optimus device selection.
5. **`libloading` (ISC)**: owner decision whether ISC counts as MIT-equivalent; otherwise write Izcal's own dynamic-loader wrapper.
6. **Full dependency-tree licence audit** (`cargo deny`) of the chosen binding crates; crates.io fields were checked for direct crates only.
7. **macOS floor**: measure on M1 (Apple7) under macOS 14 and 15 whether residency sets, `mathMode = safe`, and binary archives are needed for the FP and determinism targets; decide macOS 14 vs 15.
8. **Intel Mac demand**: share of Izcal's target users on Intel Macs (Steam shows macOS at 1.92% of all; Intel share within that is unknown).
9. **Windows machines without a D3D12 driver**: their share (Steam's DirectX page gave no totals); decides whether WARP or CPU raster is the fallback and confirms no D3D11 backend.
10. **Metal shader converter licence** and **`.metallib` format**: confirm Apple publishes no specification of AIR/metallib; if it does, re-evaluate offline compilation.
11. **Windows 10 consumer ESU end date** (13 October 2026 by recollection): confirm from Microsoft.
