# Izcal SVG: independent design critique (phase 8)

Written 20 October 2026 by a reviewer who did not write the spec. Subject: `reports/Izcal SVG.md`, draft 0.1 (line numbers below refer to that draft). Method: `.claude/skills/first-principles-spec/SKILL.md`, phase 8, and the shared phase 2c brief.

**Read against:** HGBA-2 2.3.3 (M-1 parts 1–4, the MIT-only rule, P1–P6, I-1, I-2); Stage 1 design (2.1 layers, 2.2 G1–G9); JavaScript engine spec 0.4 (6.2 JS-D4 and its H-2 rationale, 6.5, 6.9 JS-D12, JS-D15 and the consolidated decision-point list, `hg-math`, G6); DOM, bindings and event loop spec (6.1 two-phase edits, mutation log, release by ID; 6.2 DM-D5 rules 1–3; 6.5 dispatch; 6.6 shadow DOM and slots; 6.12; 6.17 crate table; 6.18; G90–G99); HTML and CSS parsing and style spec 0.3.3 (6.2 sinks, 6.6a sheet install, 6.9 computed-length type, 6.10, 6.11, 6.15 L2p and G24, G19–G24, ST-D18, ST-D20, ST-13); layout spec 0.3 (6.0, 6.1, 6.2 LY-D3, 6.5.10, 6.14, 6.18 G1 and G37–G45); graphics and rendering spec 0.3 (6.3 bounded path format, 6.4 transform row, 6.7 GR-D18, 6.8 GR-D13, 6.16, 6.24 L2g and G60–G72, 6.28); images and media spec 0.4 (6.1 MD-D20, MD-D19, G50, G53, G56, MD-53, MD-56, MD-S10, Q-MD-18); fonts and text spec (6.1 TX-D2 placement table, 6.3 OT-SVG limits, TX-D4, TX-D7, G26); resource footprint spec 0.4 (FP-11, FP-13, FP-17, FP-34, FP-36, FP-38, FP-D19); accessibility spec (G100–G109, the reduce-motion rules); networking spec (content codings in the partition service, NW-D6); DevTools spec; reconciliation 2 (Q14/OD-6, Q20, Q25, Section 4); Phase 3 ledger (G-12, G-13, A-FUT-1, A-FUT-4, A-FUT-5); the in-progress animation spec's `research_notes/Izcal animation/frame.md` (no animation report exists yet in `reports/`). All eight SVG research notes' M-1 statements were read; all 373 distinct links in the spec and notes were screened for source-code hosts.

**Overall.** The draft's architecture is right and in places better than anything shipped: one engine with two kinds of host, an explicit render tree and reference graph, materialized `use` instances built outside script, SMIL split into a scriptless timing front end over a shared effect model, and a published, deterministic budget. The weak points are where the draft asserts that something "runs unchanged" or "changes no decision" without modelling the other spec's mechanism:
- **The scriptless host.** Style, the atom table, the mutation log and the fragment store are all **per agent** in the accepted specs; a host with no agent has none of them. SMIL animating `use` `href` changes the tree that 6.1 says never changes. HTML in `foreignObject` needs element behaviours that live in `hg-html`, which G120 forbids.
- **`hg-node-store`.** JS-D4's soundness argument is that only `hg-dom`'s code writes the columns, with its barrier and a log record per write. A shared store with a public write API breaks that unless the write capability is typed.
- **Layering.** Four crate placements depend upward (L2p on L3, L3 on L4), against Stage 1 2.1 and ST's G24.
- **The budget ledger.** Its limits are an order of magnitude beyond SV-11's own 250 ms / 64 MiB bound, "document order" charging is not a pure function under incremental rebuilds (G127), and the filter-work budget makes filters vanish on zoom.
- **SV-D2.** The IEEE-binary64 argument is sound for the five basic operations, but the lint covers only FMA; Rust's own float methods include ones whose precision is documented as non-deterministic, `min`/`max` do not order signed zeros, and style's computed-length type (which carries every SVG geometry property through the cascade) may be binary32.

**Counts:** 36 findings: **9 High, 16 Medium, 11 Low**. In addition, 9 engine-source and licence items (E1–E9) and 18 reconciliation items (R1–R18).
