**Implications:** Izcal can implement the modes as a capability set of four booleans, chosen by the embedding context. MD-D20's scriptless media process is exactly "secure animated/secure static". Izcal must pick one rule for external resource documents and record it, because SVG 2 says static and Integration says animated.

| # | Finding | Numbers | Source | Date | Conf. |

**Implications:** the constant-time rule for tainted filters is a direct requirement on `hg-svg-paint`. Izcal's integer rasteriser should make timing independent of data, and that must be measured. Gradients, patterns and filters that reference elements reuse the `use` shadow-tree machinery, so build it once.

## Open questions for the spec

1. Resource documents: secure static (SVG 2 §2.3) or secure animated (Integration)? Which does Izcal pick, and what WPT evidence supports it?
2. What are Izcal's numeric budgets for `use` and template instance count, depth and per-document cost, given that the spec sets none (4.7)?
3. External `use`: same-origin only, as the spec says. Measure current engines black-box (WPT `svg/struct`) before committing.
4. SMIL: is it mapped onto the Web Animations engine (no normative basis, 6.5), or kept as a separate timing model? `discard`: in or out?
5. `context-fill` in OpenType glyphs is deprecated by OpenType but assumed by SVG 2. Which wins for `hg-text`?
6. Can constant-time tainted filters (5.5) be verified with a timing test on Izcal's integer rasteriser?
7. Should the `d` property accept only `<string>` per the CR, or also `path()` as engines ship? Black-box check needed.
8. Should at-risk `vector-effect` values and the `path-length` property be implemented now or deferred?
9. Which version of the HTML parser, with PI tokenization (7.3), does Izcal pin?
