# Izcal coding standard: error handling and type design

Compiled 18 October 2026. Primary sources were preferred: maintainers' documents and build files, postmortems, RFCs, specifications, mailing-list posts and security advisories. Per M-1 and D-S10, this note learns practices and ideas only. Where it cites another engine's build file or header, it is to establish a fact about that project's practice, not to copy its code.
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, a secondary summary of a primary source, or a well-known fact recalled but not re-fetched this session; **Low** = secondary source only.

**Scope.** This strand covers error handling and type design. Async, concurrency and code structure, and testing and performance, are covered by the other two strands. Where a rule here touches theirs (for example, `Send`/`Sync` or overflow-check cost), it says so and stops.

**Lint names.** Every lint name in this note was checked against the local toolchain on 18 October 2026: `rustc 1.99.1 (2026-10-13)` and `clippy 0.1.99`, with `cargo clippy --explain <lint>` and `cargo clippy -- -W help` (which also gives each lint's group and default level). One name was rejected in that check (`unchecked_duration_subtraction`, renamed `unchecked_time_subtraction`), and `string_to_string` no longer exists.

## 0. Frame

**The problem.** Izcal has architecture specs but no coding standard. Its code is written by people and AI tools, so a rule that a lint, a generator or a hook enforces is worth much more than one that depends on review. This strand answers two questions: how Izcal code should fail, and how its types should make misuse hard.

**What Izcal's specs already decide or constrain:**
- **Process model** (Stage 1 §1): the broker (browser process), the network, storage and GPU services are shared by all sites. Renderers are per site. So a panic in a renderer takes down one site; a panic in a shared process takes down the browser or all sites.
- **G3** bans `std::time`, `std::thread` and the like outside `hg-substrate-os`, through `clippy::disallowed_methods`/`disallowed_types` in a workspace `clippy.toml`. The same mechanism can carry error-handling bans.
- **G5**: every crate is `#![forbid(unsafe_code)]` unless listed in `unsafe-inventory.toml` with an owner. HGBA-2 §4.8: every `unsafe` block and FFI boundary is inventoried, and FFI wrappers treat foreign memory as tainted.
- **IPC** (Stage 1 §4, VER-1): `.hgidl` interfaces, generated endpoints and serializers, a fixed wire format and a generated Kani harness per message. Identity comes from the endpoint. The security note's IPC rule 5 already says a bad message closes the endpoint and kills the sender, and that `panic`/`unwrap`/`expect` on message-derived values are lint errors in broker crates (`research_notes/Izcal security scope/sandbox_ipc.md` §17).
- **DOM in `cppgc`** (Stage 1 §5.2) with generational stable node IDs (32-bit slot, 32-bit generation). Bindings are generated from WebIDL (§5.3).
- **HAL error semantics** (HGBA-2 §5.4–5.5): validation errors are sticky and never crash a service; `OutOfMemory` fails cleanly; `PolicyDenied` must be indistinguishable from `Unsupported` to content; device loss invalidates an epoch's handles.
- **Simulation** (Stage 1 §3.2): the whole multi-process browser runs in **one OS process**, and "process crash and restart" is a scheduler-injected fault. This matters for the panic strategy (Section 4).
- **Security evidence** (`exploits_mitigations.md` 9.4–9.10, 11.2): from 2024 on, denial of service is the largest RustSec category; mature Rust network crates fail through panics and resource exhaustion; the Rust↔V8 boundary is where Rust embedders break (Deno CVE-2024-27934).

**Success, measurably:** each candidate rule in Section 12 is either enforced mechanically (a named lint, a generator check, a graph-lint rule or a hook) or explicitly marked review-only; and the panic and type-confusion rules map onto targets the existing specs can test (Kani "no panic for any byte string", DST, fuzzing).

## 1. History: the two-channel model (bugs vs errors)

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 1.1 | **Midori split failures into two mechanisms**: *abandonment* (fail-fast, tear down the process) for bugs, and statically checked exceptions for recoverable errors. Recoverable errors are predictable (I/O, parse failures, bad user input); bugs are conditions the developer did not expect, after which any data touched may be corrupt, so Midori did not try to recover. Abandonment was affordable because processes were lightweight and isolated. | — | [Joe Duffy, The Error Model](https://joeduffyblog.com/2016/02/07/the-error-model/) | 2016-02-07 | High |
| 1.2 | Midori's abandonment triggers: bad casts, null dereference, out-of-bounds access, divide by zero, **unintended overflow**, **out of memory**, stack overflow, explicit abandonment, failed contracts and assertions. OOM abandoned by default; a developer could opt in to a recoverable allocation (`try new ...`) for large buffers. | — | same | 2016-02-07 | High |
| 1.3 | Midori evidence: about **90%** of .NET/Java argument-validation exceptions became preconditions (contracts that abandon); about 90% of contracts concerned nullability and numeric ranges; making unannotated overflow a bug "helped to avoid a bug" **9 times out of 10**. Midori had more release assertions than debug ones. | 90%; 9 of 10 | same | 2016-02-07 | High |
| 1.4 | Midori rejected return codes because errors could be silently ignored; it made ignoring a return value a **compile-time error** (explicit `ignore` required). Rust's `#[must_use]` on `Result` plus the `unused_must_use` lint (warn by default) is the same idea. | — | same; `rustc -W help` | 2016 / 2026-10-18 | High |
| 1.5 | **Rust's mainstream statement of the same model**: "If a Rust program panics, then it signals a bug in the program. That is, correct Rust programs don't panic." `unwrap`, `expect` and slice indexing are fine for preconditions and internal invariants; panicking "should not be used for error handling in either applications or libraries." Prefer `expect` to `unwrap`, but trivial `expect("no panic")` messages written only to satisfy a lint are noise. The author does not lint against `unwrap` himself, partly because indexing, arithmetic and `RefCell` borrows panic too and no lint catches them all. | — | [Andrew Gallant, Using unwrap() in Rust is Okay](https://burntsushi.net/unwrap/) | 2022-08-08 (addendum 2025-05-17) | High |
| 1.6 | **TigerBeetle (TIGER_STYLE)**: assertion density of at least **two per function** on average; *pair assertions* (check each property on two different code paths); "The only correct way to handle corrupt code is to crash"; "All errors must be handled"; explicitly sized integers (`u32`, avoid `usize`); all memory statically allocated at start-up; "Put a limit on everything", including every loop and queue. | ≥2 assertions/function | [TigerBeetle TIGER_STYLE.md](https://github.com/tigerbeetle/tigerbeetle/blob/main/docs/TIGER_STYLE.md) | living | High |
| 1.7 | TIGER_STYLE's evidence for "handle all errors" is a study of distributed data-intensive systems: "almost all (**92%**) of the catastrophic system failures are the result of incorrect handling of non-fatal errors explicitly signaled in software." | 92% | same (quoting Yuan et al., OSDI 2014) | living | High (quote); Medium (study not re-read) |
| 1.8 | **rustc** encodes "an error was already reported" as a type: `ErrorGuaranteed` is a zero-sized type that cannot be built outside `rustc_errors` and is produced only when a diagnostic is emitted. Holding one statically proves compilation will fail, which prevents "silently continue after an error" bugs. | — | [rustc-dev-guide: ErrorGuaranteed](https://rustc-dev-guide.rust-lang.org/diagnostics/error-guaranteed.html) | living | High |

**Implications:** The evidence is consistent across Midori, the Rust community and TigerBeetle: **errors** (things that happen at some frequency from outside) are values; **bugs** (broken invariants) stop the unit of isolation. Izcal already has the unit of isolation Midori relied on: the process. What Izcal must add is a rule for *which* process a bug may stop (Section 4).

**Implications:** The Cloudflare outage is the cleanest public case of a Rust `unwrap` taking down a shared service, and its cause was not Rust: it was a **limit with no defined behavior when exceeded**, in a process shared by every customer, on **internal configuration treated as trusted**. The lesson for Izcal is three rules, not one: every limit has an error path, configuration and update data are untrusted input, and code in shared processes must not panic on data it did not create. The Deno and Servo cases show that the Rust↔V8/GC boundary needs type design, not just care.

## 4. Panics: strategy, FFI, DoS, OOM

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 4.1 | **C-unwind (RFC 2945)** added `extern "C-unwind"` so unwinding can cross language boundaries on purpose. Since **Rust 1.81**, a panic that would escape a non-unwind ABI function such as `extern "C"` **aborts**, "closing the longstanding soundness problem". **Analysis: what a panic costs in each Izcal process** (derived from Stage 1 §1 and §3.2; not from another browser):

| Process | Shared by | A panic reachable from attacker input means | Policy it implies |
|---|---|---|---|
| Renderer (per site) | One site's frames and workers | The attacker crashes its own site. Content can already do that (`while(1)`, allocate until OOM), so this is a reliability bug, not a security boundary failure | Panics allowed for internal invariants; web-reachable panics are bugs found by fuzzing |
| Broker, `hg-navigation` | Every site | A compromised renderer, or a malicious page through it, kills the whole browser: cross-site DoS and lost session state | **No panic on any less-privileged input** (Mojo 4.6) |
| Network, storage, GPU services | Every site | One malicious server, file or shader kills networking, storage or graphics for all sites | **No panic on any network, file or content-derived input** (3.9) |
| Simulator (`hg-substrate-sim`) | Every simulated process, in one OS process | With `panic=abort`, any real panic ends the seed | A real panic is a found bug; simulated crashes must be scheduler faults, not panics |

**Implications:** **Abort everywhere** is the right production strategy. Unwinding cannot be relied on in the renderer anyway: V8 callbacks are `extern "C"`, so a panic escaping one aborts since Rust 1.81, and catching a panic and continuing in a process that shares a V8 heap and `cppgc` DOM would continue after a bug with unknown state (Midori's argument). Abort also keeps the crash signature deterministic for DST. Because Cargo forces unwinding in test builds (4.3), any production use of `catch_unwind` would behave differently in tests than in release, which is one more reason to ban it.

## 8. Type design: newtypes, parse-don't-validate, typestate, IDs

| # | Finding | Numbers | Source | Date | Conf. |

**Implications:** Izcal is one workspace built together, with no downstream users of its crates. ## 13. Lessons for Izcal: candidate rules

Each rule says how it is enforced: **lint** (a named rustc or clippy lint, set in `[workspace.lints]` or a crate's `[lints]` table), **gen** (`hg-ipc-codegen` or `hg-webidl-codegen`), **graph** (`hg-graph-lint`, which already reads `cargo metadata`), **hook** (an `ast-grep` rule in T0), or **review** (no mechanical check). Lint names were verified against clippy 0.1.99 and rustc 1.99.1. Lints in clippy's restriction group are `allow` by default and must be enabled explicitly.

### 13.1 Trust tiers

The rules below refer to three crate tiers, declared in one workspace file (for example, a `tier` key next to `unsafe-inventory.toml`) and checked by `hg-graph-lint`:
- **Tier P (privileged or shared):** the broker and `hg-navigation`, `hg-net`, `hg-storage`, `hg-gpu`, the IPC transports, and all code generated by `hg-ipc-codegen`. Input from less-privileged processes, the network, files or update data is hostile.
- **Tier R (renderer):** `hg-dom`, `hg-bindings`, `hg-script`, `hg-style`, `hg-layout`, `hg-paint`, `hg-semantic`, `hg-dataplane`, `hg-projection`.
- **Tier T (tools and tests):** `xtask`, `hg-dst`, test harnesses, build tools.

### 13.2 Error handling

| ID | Rule | Evidence | Enforcement |
|---|---|---|---|
| ER-1 | **Two channels.** Conditions that occur at some frequency from outside the code (input, I/O, IPC, network, device loss, limits exceeded) are `Result` values. Panics and assertions are only for broken internal invariants (bugs). A `Result`-returning function must not panic on its inputs. | 1.1–1.5, 2.9 | review, plus `clippy::unwrap_in_result` and `clippy::panic_in_result_fn` (restriction) at deny in tier P |
| ER-2 | **Abort.** `panic = "abort"` in every shipping profile (`dev`, `release`, and any custom profile). `catch_unwind` is never used for recovery in production code. | 2.1, 2.4, 2.11, 4.1, 4.3 | graph: check the workspace profiles in `Cargo.toml` (package overrides cannot change `panic`, 4.3); lint: `clippy::disallowed_methods` for `std::panic::catch_unwind` and `std::panic::resume_unwind` outside tier T |
| ER-3 | **No panic on less-privileged input in tier P.** In tier P, deny: `clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic`, `clippy::todo`, `clippy::unimplemented`, `clippy::indexing_slicing`, `clippy::string_slice`, `clippy::get_unwrap`, `clippy::arithmetic_side_effects`, `clippy::unwrap_in_result`, `clippy::panic_in_result_fn`. Allow them in tests (`allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests`, `allow-indexing-slicing-in-tests` in `clippy.toml`). Remaining genuine invariants use `#[expect(clippy::..., reason = "...")]` on the smallest scope. The lints miss `RefCell` borrows, dependency panics and `Drop` (4.7), so the generated Kani harness ("no panic for any byte string") and the sequence fuzzer are the real check. | 3.1, 4.6, 4.7, 3.9 | lint (per-crate `[lints]` tables, generated from the tier file) + gen (Kani) + fuzzing |
| ER-4 | **Suppressions carry reasons and expire.** `#[allow]` is replaced by `#[expect(lint, reason = "...")]`. | 2.9, 2.13, 4.2 | lint: `clippy::allow_attributes` and `clippy::allow_attributes_without_reason` (restriction) at deny, workspace-wide |
| ER-5 | **Tier R panics are bugs, found by fuzzing.** Internal invariants may use `expect("invariant: ...")`; `unwrap` is not used outside tests (so each panic site states its invariant). Any panic reachable from web content is a P2 bug with a regression test, not a security issue, unless it crosses into a tier P process. | 1.5, Section 4 table | lint: `clippy::unwrap_used` at deny in tier R; DST and the Domato-style fuzzer report panics |
| ER-6 | **A bad message kills the sender, and the handler cannot forget to stop.** Generated handlers for less-privileged senders return `Result<_, BadMessage>`; the generated dispatcher, not the handler, closes the endpoint and asks the broker to terminate the sender. There is no `report_bad_message()` call that a handler could forget to `return` after. Messages from more-privileged senders that fail validation are bugs (the receiver may abort). | 3.8, 4.6, 6.1, 6.2 | gen |
| ER-7 | **Every limit has an error path and a fallback.** Every fixed capacity, preallocation or cap (IPC lengths, queue depths, feature counts, cache entries) returns a typed error when exceeded, and the caller has a defined fallback (reject, shed, or keep last-known-good). No `unwrap` on a capacity check. | 3.1, 3.4, 1.6 | review + hook (`ast-grep`: flag `.unwrap()`/`.expect(` directly on calls whose names start with `try_`, `push_within_capacity`, `checked_`) |
| ER-8 | **Configuration and update data are untrusted input.** Blocklists, content-blocking filter lists, feature-flag files, GPU driver blocklists, component and update manifests are parsed by the same rules as network input (ER-3 in their parsers, size limits, fuzz targets), and a parse failure keeps the last-known-good version. | 3.2, 3.4 | review + a fuzz target per format + a test that injects an oversized and a corrupt file |
| ER-9 | **Fallible allocation for attacker-sized buffers.** Small allocations may use the default (abort on OOM, 4.4). Any allocation whose size comes from IPC, the network, a file, media, fonts, images, WebGPU or JS-provided lengths uses `try_reserve`/`try_with_capacity`-style APIs and an explicit cap, and returns an error. Where the spec defines the failure (for example, ArrayBuffer allocation failure throws `RangeError`), the error maps to it. IDL fields declare maximum lengths. | 2.6, 2.8, 4.4, 4.5, 3.9 | gen (IDL max lengths, bounded allocation in Kani harnesses); review elsewhere; fuzz with an RSS limit |
| ER-10 | **Library-style errors in every `hg-*` crate.** Errors are dedicated enums near their unit of fallibility (`thiserror` may be used unmodified), with `source()` chains and std-style Display (lowercase, no trailing punctuation, no repeated cause). `anyhow` and `Box<dyn Error>` appear only in tier T binaries. `map_err(|_| ...)` that drops the source is not allowed in tier P. | 5.1–5.3 | graph: no non-tier-T crate depends on `anyhow`; lint: `clippy::map_err_ignore` (restriction), `clippy::error_impl_error` (restriction), `clippy::result_large_err` (perf, default 128 B) |
| ER-11 | **Results are always used.** | 1.4, 2.12, 2.13 | lint: rustc `unused_must_use` at deny; clippy `let_underscore_must_use`, `unused_result_ok` (restriction) at deny |
| ER-12 | **IPC errors are closed enums with no strings.** Each `.hgidl` protocol declares one closed error enum; no free-text, stack traces, addresses or paths cross a process boundary; an unknown discriminant is a bad message. | 6.3, 6.4, Section 6 implications | gen |
| ER-13 | **One generated mapping from internal errors to web exceptions.** `hg-webidl-codegen` emits, per member, the conversion from the Rust error into the WebIDL simple exception or `DOMException` name that the spec algorithm throws, with a fixed `&'static str` message. No internal error's Display reaches script. Network failures of every kind become the Fetch network error (`TypeError`); cross-origin script errors are muted. | 7.1–7.4 | gen + a privacy test: CORS failure, DNS failure, TLS failure and connection refused produce byte-identical exceptions |
| ER-14 | **Panic and error messages contain no page or user data.** Crash reports carry panic messages (Firefox does, 2.5; Izcal's D-S4 sends minidumps), so `panic!`/`expect`/`assert!` messages in tier R and P are string literals naming the invariant; they never format URLs, DOM content, header values or user input. | 2.5; D-S4 | hook (`ast-grep`: flag `panic!`, `expect(`, `assert!` with format arguments in tier P and R crates); `clippy::expect_fun_call` helps |
| ER-15 | **Errors are deterministic.** Error values and messages compared or hashed by DST contain no addresses, no backtraces and no hash-map iteration order. Backtraces are captured only by the crash handler. | Section 5 implications; Stage 1 §3 | lint: `clippy::disallowed_methods` for `std::backtrace::Backtrace::capture` and `force_capture` outside the crash-handler crate (same mechanism as G3) |
| ER-16 | **Simulated crashes are faults, real panics end the seed.** In `hg-substrate-sim`, "process crash" is a scheduler action that drops a simulated process's state; it is never produced by panicking. A real panic aborts the run and is filed by `hg-dst` as a bug with its replay command. | 4.1, 4.3, Stage 1 §3.2, §7.4 | design rule in `hg-substrate-sim`; review |
| ER-17 | **No panic crosses FFI, and no FFI error is silent.** Every `extern "C"` callback from V8 is generated; its body returns `Result`, and the generated shim turns an error into a pending JS exception or a documented failure value. Hand-written `extern "C-unwind"` is not used. | 2.3, 4.1 | gen; lint: rustc `ffi_unwind_calls` at deny |
| ER-18 | **Assertions on own state are encouraged.** In all tiers, cheap `assert!`s on the crate's own invariants stay on in release (they are bugs, and abort is the right response); expensive ones use `debug_assert!`. In tier P, an assertion must never test a value that came from a less-privileged process (that is ER-6's job). | 1.3, 1.6, 4.6 | review (the tier-P part is covered by the Kani harness) |

### 13.3 Type design

| ID | Rule | Evidence | Enforcement |
|---|---|---|---|
| TY-1 | **Newtypes for every ID and unit.** Node, frame, navigable, site instance, process, endpoint, sequence and device-epoch IDs; CSS px vs device px; byte lengths vs element counts. Raw `u32`/`u64`/`usize` never appear as an ID in a public `hg-*` signature. IDs do **not** implement `Default` or public `From<u32>`, so a zero or forged ID cannot be made by accident. | 8.4, 8.5 (C-NEWTYPE, C-CUSTOM-TYPE) | hook (`ast-grep`: public fns in `hg-*` with parameters named `*_id` of primitive integer type); review |
| TY-2 | **Generational IDs for anything referenced across a lifetime boundary.** Slot plus generation (`u32` + `u32`, Stage 1 §5.2); lookup returns `Option`; a slot whose generation would overflow is retired, never wrapped. A property test proves a stale ID never resolves to a new object. | 8.3; Stage 1 §5.2 | review + property test (already planned) |
| TY-3 | **Parse at the boundary, accept only parsed types inside.** Every trust boundary (IPC, network, files, config, JS→Rust conversion) produces refined types (`Origin`, `Site`, validated URL and path types, bounded strings, `NonZero*`); their fields are private and `TryFrom`/parsers are the only constructors. Privileged code never takes a `String` that it later parses. | 8.1, 8.4; `sandbox_ipc.md` rule 3 | gen for IPC and bindings; review elsewhere |
| TY-4 | **Make invalid states unrepresentable.** Enums instead of `bool` flags or several `Option`s; unions instead of optional-field combinations; no parallel arrays; no `Count`/`Last` sentinel variants. | 8.4, 8.5 | gen for `.hgidl`; lint: `clippy::fn_params_excessive_bools`, `clippy::struct_excessive_bools` (pedantic) |
| TY-5 | **Typestate for security-relevant lifecycles.** Process site-lock (`Renderer<Unlocked>` → `Renderer<Locked>`), endpoint binding, navigation commit and capability attenuation (rights can only shrink) are encoded in types, with sealed state markers. | 8.2; HGBA-2 I-1; `sandbox_ipc.md` rules 1–2 | review |
| TY-6 | **No `#[non_exhaustive]` and no wildcard arms on Izcal-owned enums.** Exhaustive matching is how a new message, error kind or node type reaches every handler. Use `#[non_exhaustive]` only on a crate Izcal publishes for outside users. | 8.6 | lint: `clippy::wildcard_enum_match_arm` (restriction) in tier P and generated code; hook: flag `#[non_exhaustive]` in workspace crates |
| TY-7 | **Seal traits that define authority.** Traits whose implementations mint or carry authority (handle kinds, capability rights, `GarbageCollected` wrappers, tree-access traits' write side) are sealed so only their owning crate can implement them. | 8.2, 8.5 (C-SEALED) | review |
| TY-8 | **Constructors validate; builders return `Result`.** Plain constructors (`new`, `try_new`, `parse`) for types with invariants; builders only for configuration with many optional fields, and `build()` validates and returns `Result`. `From` impls never panic. | 8.5 (C-BUILDER, C-VALIDATE) | lint: `clippy::fallible_impl_from` (nursery) at deny |
| TY-9 | **`Send`/`Sync` are part of the type's contract.** Types tied to an isolate, a `cppgc` heap or a sequence are `!Send` and `!Sync` by construction (a `PhantomData` of a non-`Send` marker), with a compile-time assertion; cross-sequence access goes through `SequenceBound<T>`. `unsafe impl Send/Sync` is only in inventoried crates with a `// SAFETY:` comment. (Concurrency design belongs to the async/concurrency strand.) | 8.5 (C-SEND-SYNC), 10.5 | lint: `clippy::non_send_fields_in_send_ty` (nursery), `clippy::arc_with_non_send_sync` (suspicious); compile-fail tests; G5 inventory |
| TY-10 | **No `RefCell` borrow across a call that can run script or GC.** Functions that may re-enter script or trigger `cppgc` GC take a zero-sized token parameter (name to be chosen, for example `ReentryToken`); a live `Ref`/`RefMut` across a call that takes the token is forbidden. Prefer `Cell` for `Copy` fields, per-field cells and clone-out. In tier P, `borrow_mut` failures are errors (`try_borrow_mut`) or the design avoids `RefCell`. | 3.6, 9.1–9.3 | gen (bindings pass the token); hook or a custom lint (no stock lint exists, 9.3); GC-stress and re-entrancy fuzzing |
| TY-11 | **Indices and arenas over long-lived references.** GC-managed objects are reached through handles and stable IDs, never Rust references held across script or GC; phase-pure work (style, layout, paint) may borrow immutable inputs for the phase. Arena-plus-typed-index (`IndexVec`-style) is the default for engine graphs. | 8.3, 9.4, 2.15 | review |
| TY-12 | **Size budgets for hot types.** `const _: () = assert!(size_of::<T>() == N);` (64-bit) for the node header, data-plane entries, IDs, `Task`, IPC message headers, and every enum on a hot path; a change in size is a reviewed diff. | 2.15, 2.16, 4.5 | rustc (const assert); lint: `clippy::large_enum_variant`, `clippy::result_large_err` (perf, on by default), `clippy::large_futures` (pedantic) |
| TY-13 | **Explicit integer widths and conversions.** `u32` for slots and generations; `usize` only for in-memory indexing. No `as` between integer types in tier P and generated code: use `From`/`TryFrom`. Arithmetic on untrusted values uses `checked_*`. `overflow-checks = true` for tier P crates in release (a per-package override). Whether to enable it in tier R release builds is a performance-lab measurement. | 10.1–10.3, 2.10, 2.7, 4.3 | lint: `clippy::as_conversions` (restriction), `clippy::cast_possible_truncation`, `clippy::cast_sign_loss`, `clippy::cast_possible_wrap`, `clippy::cast_lossless`, `clippy::checked_conversions` (pedantic), `clippy::arithmetic_side_effects` (restriction) in tier P; Cargo profile override |
| TY-14 | **Encapsulated `unsafe` with written contracts.** Every `unsafe` block has a `// SAFETY:` comment directly above; every `unsafe fn` and `unsafe trait` has a `# Safety` section; one unsafe operation per block; safe wrappers expose no unsafe API; unsafe blocks are minimal. | 2.2, 2.9, 10.4, 10.5; G5 | lint: rustc `unsafe_code` (forbid outside the inventory, G5), `unsafe_op_in_unsafe_fn`, `unsafe_attr_outside_unsafe`, `missing_unsafe_on_extern` at deny; clippy `undocumented_unsafe_blocks`, `multiple_unsafe_ops_per_block` (restriction), `missing_safety_doc`, `unnecessary_safety_comment`, `unnecessary_safety_doc`, `ptr_as_ptr`, `ref_as_ptr` at deny |
| TY-15 | **Documented failure.** Public functions document `# Errors` and `# Panics` (and `# Safety`). | 8.5 (C-FAILURE), 2.9 | lint: `clippy::missing_errors_doc`, `clippy::missing_panics_doc` (pedantic), `clippy::missing_safety_doc` |

### 13.4 The Rust↔V8 boundary (type confusion)

| ID | Rule | Evidence | Enforcement |
|---|---|---|---|
| V8-1 | **Generated wrapper tags in inheritance ranges.** `hg-webidl-codegen` assigns each WebIDL interface a `CppHeapPointerTag` value by depth-first pre-order over the interface inheritance tree, so each interface's descendants form one contiguous range; unwrapping as interface `I` checks the range `[id(I), id(last descendant of I)]`. The generator asserts uniqueness and range containment at build time; no tag is hand-written. Non-wrappable `cppgc` objects use the separate embedder non-wrappable range. | 11.2, 11.3 | gen (plus a build-time assertion) |
| V8-2 | **A second, Rust-side type check after unwrap.** Each wrapped Rust object stores its interface ID, and generated unwrap code compares it before producing `&T`, so correctness does not depend on whether the V8 build checks tags. Measure its cost; drop it only if the sandbox is mandatory in every build Izcal ships and the perf lab shows a cost. | 11.4 | gen |
| V8-3 | **No raw pointers in V8 objects.** No `v8::External`, internal field or embedder data slot holds a raw Rust pointer; JS-to-Rust object links go only through `cppgc` wrapping (`Object::wrap`/`unwrap`) or through stable generational IDs. | 3.5, 11.5 | lint: `clippy::disallowed_methods` for `v8::External::new` and the internal-field/aligned-pointer setters outside generated code; G6 limits where `v8` is visible |
| V8-4 | **Unwrapped pointers live only on the stack.** The `UnsafePtr<T>` from `unwrap` is converted, inside generated code, into a non-`Send` guard borrowed from the current `HandleScope`, so it cannot be stored in a struct or carried across an await or a re-entrant call. | 11.3 | gen; type design (lifetime tied to the scope) |
| V8-5 | **JS values reach Rust only through generated WebIDL conversions.** Every `Local<Value>` → Rust conversion is the WebIDL conversion algorithm for the declared type, returning `Result<T, TypeError-or-RangeError>`; unchecked casts on `Local` handles are not used outside generated code. | 7.1, 11.1 | gen; hook (flag unchecked `Local` casts in hand-written code) |
| V8-6 | **No borrowed view of a JS buffer across script.** Rust never holds a `&[u8]`/`&mut [u8]` into an `ArrayBuffer`/`SharedArrayBuffer` backing store across any call that can run script or GC, or across async work; it copies out, or re-validates length and detachment after the call. Resizable and detachable buffers are covered by fuzzing. | 11.6; TY-10 | gen (binding signatures) + review; closes the gap the security strand found |

### 13.5 What Izcal deliberately does not adopt

- **Unwinding and `catch_unwind` recovery** (Servo's model): Izcal's processes are the recovery unit, V8 callbacks abort on escaping panics anyway, and continuing after a bug in a process that holds a V8 heap is what Midori argued against.
- **`#[non_exhaustive]`, sealed-for-semver traits and other stability items** from the API guidelines, for workspace-internal crates (Section 8 implications).
- **`flexible` error enums** in IPC (Fuchsia's choice for separately versioned peers; Izcal's peers come from one build).
- **TigerBeetle's static allocation**: right for a database with a fixed workload, wrong for a browser whose memory need is set by the page. The part that transfers is "put a limit on everything" (ER-7, ER-9).
