# Izcal fonts and text: text shaping and script requirements

Compiled 2026-10-19. Primary sources were preferred (Microsoft script development specifications, Unicode standards and annexes, W3C specifications, the HarfBuzz manual and API reference, project READMEs, issue trackers).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, a search-result summary of a primary source, or a vendor claim without data; **Low** = secondary source only, or recalled and not re-read this session.

**Method notes.**
- This strand follows phases 2 and 3 of `.claude/skills/first-principles-spec/SKILL.md` for the frame in `frame.md`. It records requirements, ideas and measured evidence only (M-1). **No HarfBuzz, rustybuzz, HarfRust, Allsorts or browser source code was read.** Where a search result summarized a source file or commit message, the row says so and is graded Medium at best.
- The questions were researched in priority order: what a complete shaper must do per script (Microsoft script specifications, USE, UAX 53, UTS 51), then the HarfBuzz family as evidence (sizes, tests, limits, clusters, break flags), then browser caches and segmentation, real-world failures, corpora, and line-breaking interplay.
- The session-wide web-search budget ran out after 9 searches; the remaining ~17 lookups were direct fetches of known primary pages. Items not re-checked this session are graded Medium or Low and listed in "Gaps".
- "Shaper" here means: Unicode text run (one script, one direction, one font, one style) → glyph IDs, advances, offsets, cluster map and break-safety flags. Itemization, font fallback, bidi and line breaking are inputs and consumers.

## 1. Script families: what a complete shaper must do

| 1.1 | **Indic shaping model (Microsoft).** Text is split into syllable clusters; character properties are *static* (from Unicode) and *dynamic* (read from the font: a consonant is "half", "below-base", "post-base", "pre-base reordering Ra" or "reph" according to which feature lookups cover it). **Implications:** A complete shaper is a **set of script engines driven by Unicode properties plus per-engine syllable grammars**, and Microsoft's specifications are the only normative description of engine behaviour (OpenType itself does not specify the reordering). Izcal should encode each engine's grammar and reordering as **declarative data checked against the Microsoft text** (cluster grammars as regular expressions over UCD-derived classes, compiled at build time from the pinned UCD), so that Unicode upgrades are data changes and every reordering decision can be traced to a specification step (the frame's visibility goal).

**Implications:** Izcal's shaper output contract should carry, per glyph, a **cluster index into the source text at a fixed, documented granularity** (characters, with grapheme grouping computed separately from UAX 29) plus break and concat safety flags, so caret, selection, hit testing and the semantic plane all derive from one map. CSS feature mapping, tag selection and fallback positioning are spec-anchored tables, not heuristics, and belong in generated data with test vectors.

**Implications:** The evidence sizes Izcal's shaper at roughly **17–25 KLOC of Rust for shaping logic** plus generated tables, with a ~2,250-case black-box corpus available as an oracle. Izcal should **never run font-embedded code** (Wasm shaper): it violates bounded resources and I-2, and no browser ships it.

**Implications:** Word caches are the proven speed technique, but they **change output** whenever a font has contextual rules across spaces, and Gecko's cache is per process and memory-pressure-driven (non-deterministic). Izcal's cache must be **observationally transparent**: key on (font identity incl. variations, features, script, language, direction, text), reuse only when the shaper reports the word boundary as safe to concatenate, be partition-keyed (FP-36), and its presence must not change any output bit (B1). Izcal must measure hit rates and shaping share itself.

## 6. Line breaking, justification and spacing interplay

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 6.1 | **Unsafe-to-break**: a glyph flag (API since 1.5.0) meaning that breaking the text at the start of its cluster and shaping the parts separately would give a different result; absent the flag, the line breaker can slice the paragraph's shaped run and **skip reshaping each line**. **Unsafe-to-concat** (since 4.0.0, opt-in because it costs) supports the reverse: growing a segment until its edge is concat-safe. HarfBuzz notes it has no end-of-text flag position. | — | [HarfBuzz API: hb-buffer](https://harfbuzz.github.io/harfbuzz-hb-buffer.html) | — | High |
| 6.2 | Blink's shaping line breaker finds the ideal break, scans back to a break opportunity, and **reshapes only line starts/ends that are not safe-to-break**; a 2018 bug showed line-end results falling out of sync with the breaker offsets. | — | [Chromium issue 40577755](https://issues.chromium.org/issues/40577755) (search summary) | 2018 | Medium |
| 6.3 | **Kashida**: CSS Text 3 says justification "must not introduce gaps between the joined typographic letter units of cursive scripts such as Arabic"; the UA "may translate space ... into cursive elongation". HarfBuzz added a **safe-to-insert-tatweel** flag (5.1.0) for Arabic, Mongolian, Syriac. `text-justify` is at risk in the CR. | — | [CSS Text Module Level 3 (CRD)](https://www.w3.org/TR/css-text-3/) §6.4; hb-buffer API (6.1) | 2026-08-14 | High |
| 6.4 | **Letter-spacing**: UAs "should not apply optional ligatures" when letter-spacing or justification adds space, but `font-feature-settings` takes precedence; "Authors should avoid applying letter-spacing to cursive scripts", and if the UA cannot expand cursive text without breaking joins it "must not apply spacing" between that script's letter units. InDesign disabled ligatures above 0.25 em tracking (2012). | 0.25 em | CSS Text 3 §7.2; [Malkin 2012](https://lists.w3.org/Archives/Public/www-style/2012Jul/0377.html) | 2026-08-14 | High |
| 6.5 | **Shaping across element boundaries**: must not be broken across inline boxes when there is no effective formatting change, and must be broken when margin, border or padding between them is non-zero. | — | CSS Text 3 §7.3 | 2026-08-14 | High |

**Implications:** Line breaking and shaping are one loop: Izcal's shaper must emit **break-safety and concat-safety flags as first-class output**, and its line breaker must use them to reshape only at unsafe edges, with a debug mode that reshapes every line and checks equality (HarfBuzz's VERIFY flag, since 3.4.0, is the precedent). Kashida, letter-spacing and inline-boundary rules are spec-anchored inputs to the shaper call, not post-processing.

## Requirements list for Izcal's shaper (ideas only, M-1)

1. **Contract**: input = text run (one script, direction, font instance, language, features, style-derived spacing); output = glyph IDs, advances, offsets, per-glyph source cluster (character granularity, documented monotonicity), unsafe-to-break, unsafe-to-concat, safe-to-insert-tatweel, and a provenance record (engine, lookup indices applied) for visibility.
2. **Engines**: default/Latin-Greek-Cyrillic; Arabic-type joining (Arabic, Syriac incl. `fin2/fin3/med2`, N'Ko, Mongolian with FVS1–4, Adlam, others by Joining_Type) with UAX 53 AMTRA; Hebrew; Indic v1 and v2 for 9 scripts; Khmer; Myanmar; Thai/Lao; Hangul; USE for the 91 listed scripts; each with its syllable grammar compiled from the pinned UCD and Microsoft override data.
3. **Engine routing table** per script is explicit data, versioned, and checked against Microsoft's lists; divergences from other implementations are documented decisions.
4. **Tables**: GSUB (all 8 lookup types incl. reverse chaining), GPOS (all 9 incl. cursive, mark-to-ligature), GDEF (classes, mark filtering sets, ligature carets), `cmap` 14 variation sequences, feature variations and variable-font deltas; AAT `morx`/`kerx`/`trak` as a separate interpreter; `kern` (legacy) fallback.
5. **Normalization in the shaper**: compose/decompose by font cmap coverage; ccc reordering; split-vowel decomposition; CGJ respected.
6. **Fallbacks**: mark positioning by combining class when GPOS lacks marks; Arabic presentation-form fallback; dotted-circle insertion per Microsoft rules (configurable); `.notdef` only after font fallback is exhausted; default-ignorables invisible.
7. **Emoji**: UTS 51 sequence recognition used by itemization and fallback (whole sequence to one font), VS15/VS16 presentation choice, ZWJ fallback display, tag sequences terminated by CANCEL TAG.
8. **Feature selection**: generated BCP 47 → OpenType script/language tags with `dflt` fallback; CSS Fonts 4 mapping of `font-variant-*`, `font-kerning`, `font-feature-settings` precedence; vertical `vert`/`vrt2` (never both) with UAX 50 orientation.
9. **CSS rules in the shaper call**: no optional ligatures under letter-spacing unless forced by `font-feature-settings`; no spacing inside cursive joins; shaping continuous across inline boxes unless margin/border/padding intervenes; kashida only at safe-to-insert points.
10. **Fuel**: canonical, platform-independent limits on ops per input character, nesting depth and output length; exhaustion gives a specified deterministic result and a diagnostic; limits tuned on the largest real fonts.
11. **No font-embedded code**: no Wasm shaper, no Graphite unless the owner decides otherwise (and then in the same fuel model).
12. **Caching**: word/segment cache reused only at concat-safe boundaries, partition-keyed, bit-identical with the cache disabled (tested by a no-cache reference path, B5).
13. **Verification mode**: reshape-every-line and split-and-compare checks in CI; differential runs against HarfBuzz and OS shapers as black boxes; text-rendering-tests and a per-script real-text corpus at zero unexplained divergences.
