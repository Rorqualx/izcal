# Izcal fonts and text: frame

Written 19 October 2026 (phase 1 of the first-principles-spec method).

## The problem and who has it

Every page is mostly text. Izcal must turn a string, a style and a set of font files into glyph positions that layout can measure and pixels the compositor can draw, for every script Unicode encodes. HGBA-2 2.3.0 (M-1 part 1) excludes every library that does this work: HarfBuzz and its ports (rustybuzz, HarfRust), Fontations (read-fonts, skrifa), FreeType, Parley and Fontique, swash, cosmic-text, ICU4X segmenters and OTS. Izcal builds its own font parsers, web-font validation, font matching and fallback, Unicode algorithms, shaper, rasterizer and hinting, glyph caches and the text measurement interface that layout uses. The owner's direction (19 October 2026): **no shortcuts for time or complexity; staging only for a first-principles reason; cost is a planning fact.** Font parsing has been one of the most exploited attack surfaces in computing, so security is treated from first principles.

Who has the problem:
- **People reading**: text in their own script must render correctly (shaping, bidi, line breaking, emoji), crisply and quickly, and a hostile font must never compromise them or fingerprint them.
- **Web developers**: web fonts must load predictably (CSS Fonts, Font Loading API, `font-display`), metrics must be stable, and they need to know which font rendered and why a fallback happened.
- **Layout, canvas, SVG, MathML and the semantic plane**: they need shaped runs, break opportunities, metrics and glyph outlines through one deterministic interface.
- **Izcal's engineers and agents**: text output must replay bit-identically (B1) on every OS and ISA, and the text stack must be testable against specifications without other engines' code.

## What Izcal's specs already decide or constrain

- **HGBA-2 2.3.0** (`reports/HGBA 2 browser architecture spec.md`): M-1 parts 1–4 (no engine libraries; "fonts and text shaping" and "renderer and rasterizer" are named as Izcal's own; standards data such as the UCD are data, not code; other engines are black-box differential signals only); P1–P6; I-1 (one renderer per (site, container)), I-2 (zero ambient authority), I-6 (Spectre confidentiality from process isolation). Section 4.4 (WebRender, wgpu) is superseded. The 2.2.x text cited Fontations/Skrifa as evidence that Rust font stacks work (Section 4.8 rationale); under 2.3.0 that is evidence only.
- **HGBA-3** (`reports/Future software browser engine.md`): B1 deterministic substrate (DET-1: 1,000 of 1,000 bit-identical replays, ≤1% cost), B5 incremental core with a from-scratch reference path, B8 semantic plane, B9 agent principal, B10 AI off by default; VER-1's Tier 1 verified parsers list "image, font and media container headers"; PRIV-2 (linkability ≤1%, residual entropy in discrete surfaces such as font enumeration).
- **Stage 1 design** (`reports/HGBA Stage 1 architecture design.md`): Section 1 process map (utility processes do "font parsing"); Section 2 crate layers and G1–G9; Section 3 determinism; D-S1 anti-fingerprinting: readback surfaces including **`measureText`-class metrics get seeded noise**, font enumeration is normalized; 13.2 "Text and input" row assumed Parley (Fontique, HarfRust, ICU4X) and "all scripts render in Stage 1" (superseded by 2.3.0 for the libraries; the all-scripts requirement stands); 7.5 fuzzing lists font headers.
- **JS engine spec draft 0.3** (`reports/Izcal JavaScript engine.md`, owner decisions accepted): `hg-ucd` holds Unicode data tables "shared with the text stack"; `hg-intl` implements UAX 29 segmentation, UAX 15 normalization, UTS 10 collation for ECMA-402; `hg-cldr-build` compiles pinned CLDR, UCD and tz; B1 rules for Intl data (versions part of the build, recorded); **JS-D15** (timing-dependent decisions are recorded B1 inputs; production never waits on background work); JS-D12 (cross-ISA identity, no FMA contraction, one implementation of each math function); G13 (engine crates reach clocks, entropy and threads only through the substrate).
- **Resource footprint spec draft 0.3** (`reports/Izcal resource footprint.md`, owner decisions accepted): **FP-D13 (a)** every locale, hyphenation dictionary and codec ships in every build, identical everywhere, never fetched because a page asked; **FP-D14 (a)** glyph atlases per (site, container, partition), 256 KiB† growing to ≤ 2 MiB†, released with hidden tabs' tiles; **FP-D19** no device-dependent web-observable limits; the session image (system font list and fallback tables) is built by a strictest-tier utility process, sealed, immutable for the session, with a PRIV-2-filtered per-page view; no font parsing at site-process start-up; in-process content caches keyed by partition; FP-36 cross-partition probing suite; budgets in §8.2 (FP-2 empty site process ≤ 4 MiB†, FP-5 median page ≤ 32 MiB†, FP-14 GPU, FP-25 installer ≤ 50 MiB† excluding the web-observable data set, whose placeholder is ≤ 24 MiB† on disk).
- **Security scope 0.3** (in review, `../security-scope` worktree): renderers link no OS UI or font libraries (6.7); utility process entry points include fonts, with outputs normalized before crossing (bitmaps, glyph outlines); IPC-R15 no web-format parsing in the broker; SEC-12 Rust decoders for images and fonts; Q-SEC-13 recommends "unmodified non-browser crates where they exist", which 2.3.0 now excludes for fonts (amendment needed).
- **Coding standard 0.3.1** (in review): tiers P (shared processes, never panic), R (per-site), O (OS substrate), T (tools); CS-TY-12 checked arithmetic; the GPU service is tier P.

## What success looks like (measurable)

Candidate target dimensions, to be made falsifiable in the spec:
- **Correctness**: WPT `css/css-fonts`, `css/css-text`, `css/css-writing-modes`, `css/css-font-loading` pass rates; 100% of Unicode's own conformance files (LineBreakTest, GraphemeBreakTest, WordBreakTest, SentenceBreakTest, BidiTest, BidiCharacterTest, NormalizationTest, emoji test data) at the pinned Unicode version; a shaping corpus per script with zero unexplained divergences.
- **Security**: zero memory-unsafe code in font and shaping paths reachable from content; parsers generated from format descriptions and proved panic-free and bounded; bounded resources per font and per text run (canonical fuel); every historical font CVE class as a regression test; no font parsing in the broker or GPU service.
- **Determinism**: same font bytes, text, style and seed give bit-identical shaping, metrics and glyph coverage on macOS, Linux and Windows and on x86-64 and AArch64.
- **Privacy**: font-derived fingerprinting entropy within PRIV-2; no cross-partition channel through font or glyph caches (FP-36).
- **Performance and footprint**: shaping and rasterization throughput, first-text latency, web-font load to first render, memory per page and per atlas within the footprint budgets.
- **Visibility**: text facts no browser exposes today (which font, which fallback step, which shaping rule, which break rule), anchored to specification steps.
