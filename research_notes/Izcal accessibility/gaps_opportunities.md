# Izcal accessibility: gaps_opportunities

Compiled 19 October 2026. Primary sources were preferred (survey result pages, specifications and editor's drafts, the published CDP protocol definition, vendor documentation, maintainers' and experts' own posts, WHATWG and W3C issue and minutes text, papers).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, secondary coverage that quotes the primary, a vendor claim without data, or a row carried from an earlier Izcal note without re-reading its source this session; **Low** = secondary source only, a single-author unreplicated measurement, or the researcher's recollection.

M-1 note: no engine source code was read for this note. No code files, headers, commits, diffs, code-review pages or source browsers of Blink, Gecko, WebKit, AccessKit, Flutter, PDF.js, axe-core, Playwright or any screen reader were opened. Search results that pointed at searchfox, a Gecko commit mirror and a WHATWG commit diff were not opened. The CDP `Accessibility` domain was read from the **published protocol definition** (`browser_protocol.json`, the same input `hg-cdp` uses under DT-D11), which is an interface definition, not engine code. GitHub was used only for README prose, issue and comment text (via the issues API), and licence metadata. Not read: the ARIA-AT app's support tables (the app did not render to text), the WebAIM Screen Reader Survey #10 page itself (carried from earlier Izcal notes), the Accessibility Insights for Windows "Listen" page (404), DebugBear's Lighthouse page (connection refused), Microsoft's current Read Aloud privacy statement, and the HTML Standard's history of the hit-region removal.

**Method notes**
- About 20 web searches were used of the shared budget of about 30. Later rows came from fetching known primary pages directly (stateofhtml.com, webaim.org, developer.chrome.com, firefox-source-docs, wicg.github.io, w3c.github.io, FTC, arXiv, Bugzilla, the GitHub issues API, the Stack Exchange API).
- Several rows are carried from earlier Izcal notes (`research_notes/Izcal DevTools spec/*`, `research_notes/Browser user pain points 2026/accessibility.md`, `research_notes/Izcal PDF/rendering_text_accessibility.md`); each says so and is graded Medium unless re-read here.
- This strand stays on gaps and opportunities. History, specifications, platform APIs, performance, security and privacy, and AT interaction UX are other strands; they are touched only where a gap needs them.
- Token-cost figures for agent snapshots come from one vendor-author post and from earlier notes; none were reproduced.

**Implications for R1–R4.** Overlays failed on six counts, and each maps to a rule Izcal already has or should add. ## Open questions

1. **Which accname derivation steps can be traced at zero cost when tracing is off?** This needs a B5 design decision and a measurement, not research.
2. **What does each shipping engine send to each OS for the same live-region update?** Only black-box measurement can answer this (OS event listeners: Accessibility Insights for Windows, macOS Accessibility Inspector, Accerciser), since the coalescing rules are stated only in engine code. Record it in `compat/observations/`.
3. **Does Playwright compute roles and names itself or read the browser's tree?** The docs do not say (4.4, 5.6). A black-box test with a page where browsers disagree would settle it, and it matters for whether Izcal's `getByRole` results can differ from Chrome's under the same Playwright version.
4. **What do Playwright MCP and Chrome DevTools MCP snapshots cost on a fixed corpus?** Only one vendor-author measurement exists (7.4). Izcal should measure tokens per snapshot and per diff on its own corpus before setting an agent target.
5. **When and why exactly were canvas hit regions removed from the HTML Standard?** The issue threads show they were treated as dead by 2016 and never shipped beyond flags; the removal date and the stated reason were not found (10.4).
6. **Is there a WebAIM practitioners survey after 2021?** None was found; the 2021 figures (1.1–1.4) may be stale.
7. **Did Chrome DevTools add the accessible description to Computed Properties after 2020** (4.2)? This needs a black-box check of current Chrome.
8. **Edge Read Aloud and Chrome Read aloud**: where does page text go, and can pages enumerate the voices (9.5, 9.6)? This needs the vendors' current privacy statements.
9. **Status of the WPT AAM (Acacia) tests in 2026**: is the `--enable-accessibility-api` flag still off by default, and are the macOS and Windows executors implemented (5.8)? Izcal would want to run them against its own adapters.
10. **Can Izcal implement the remote end of AT Driver for its own test-only reference AT model** without implying that model stands in for real screen readers? This is a design question for the synthesis; DT-D6 already says the view does not replace real screen-reader testing.
