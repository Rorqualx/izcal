Compiled 19 October 2026. Primary sources were preferred (OS vendor documentation on Microsoft Learn, developer.apple.com and developer.android.com, the macOS SDK's public headers, the GNOME/freedesktop AT-SPI developer guide, W3C Core-AAM, screen-reader vendors' user guides and issue trackers, engine teams' prose blog posts).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, secondary coverage that quotes the primary, a vendor claim without data, or a well-known fact not re-checked this session; **Low** = secondary source only, or the researcher's recollection not checked against a source this session.

M-1 note: no browser-engine or AccessKit source code was read for this note. No code files, headers, commits, diffs, code reviews or source browsers of Chromium, Gecko, WebKit, Servo, Ladybird or AccessKit were opened. Where this note says what Chrome or Firefox "does", the evidence is their teams' prose, and it is evidence to reason from, not a shape to copy.

**Implications:** UIA's provider must live in the broker (it owns the HWNDs). It is pull-based and synchronous per call, so the broker has to answer from a local copy of the tree, never by a synchronous IPC hop to a renderer. `ProviderOptions_UseComThreading` with MTA-threaded providers lets the adapter answer from a dedicated thread reading an immutable snapshot of the semantic plane (B8), so a busy broker UI thread does not stall screen readers. Raise events only when `UiaClientsAreListening()` or AdviseEvents says someone is listening.

**Implications:** A UIA-only Izcal would, as of October 2026, put NVDA (the most-used free reader, 65.6% "commonly used") on its fallback path, which its maintainers call weaker, and JAWS behaviour is unverified. History (Edge Legacy 2015–17) says UIA-only web content shipped to users before AT vendors caught up is effectively inaccessible for one to two years. Izcal's Windows adapter therefore needs **both** a native UIA provider (Narrator, Voice Access, Magnifier) and an MSAA+IA2 provider (NVDA, JAWS), with the IA2 IDL (BSD-3) used as a specification. Izcal must also let NVDA/JAWS inject into the **broker** process: no binary-signature or DLL-load mitigation on the broker that blocks AT DLLs, and the IA2 tree must be answerable in-process from the broker's cached copy. That injected code runs next to the broker, which is a security trade-off the security spec must record.

Rows: Windows from 3.5–3.10; macOS 4.14–4.16; Linux 5.13; Android 7.8–7.10; iOS 8.3. "Recollection" cells are Medium.

**Implications:** Seven preferences have seven different shapes per OS, several are missing on some platforms, and text scale is non-linear on Windows and Android. Izcal should define one broker-side, typed **user-preference record** (with "unknown" as a value), refresh it on each OS change signal, log every change as a recorded input for deterministic replay, and expose only coarse values to content (fingerprinting: every preference is a bit of entropy).

## Open questions and black-box measurements needed

1. **JAWS and Narrator on UIA-only web content (2026):** no Freedom Scientific statement was found. Measure JAWS 2026 and Narrator with a UIA-only and an IA2-only Izcal build on the same pages (browse mode, tables, live regions, forms).
2. **NVDA fallback quality:** measure NVDA 2026.2 with "Use UIA … Chromium" = Yes against Chromium 14x to set the bar a UIA-only path must reach (row 2.6–2.7).
3. **IA2 marshalling:** whether Izcal must ship and register an IA2 proxy/stub DLL for out-of-process IA2 clients, or can rely on NVDA/JAWS injecting their own (row 2.5). Only engine source would say what Chrome/Firefox do; test black-box with a minimal IA2 provider.
4. **Broker hardening vs AT injection:** which Windows process mitigations (binary signature, DLL load policy, CFG/CET) block NVDA/JAWS hooks. Test each mitigation against both readers.
5. **macOS main-thread and timeout:** confirm that AppKit dispatches AX requests only on the main thread, and measure VoiceOver's effective `AXUIElement` timeout (default undocumented, row 4.4–4.5) by stalling the main thread.
6. **Text-marker semantics:** the macOS 26 header gives names, not behaviour (e.g. which marker counts as "next" across element boundaries, `AXTextMarkerIsValid` after mutations). Probe VoiceOver with a test provider; WebKit/Chromium behaviour may only be observed black-box.
7. **UIA event coalescing:** Microsoft's coalescing/duplicate-detection guidance could not be fetched; re-fetch and record the rules, then measure NVDA/Narrator under 1,000 events/s.
8. **UIA Remote Operations status:** whether it is GA in Windows 11 24H2/25H2 and which ATs use it (row 1.8).
9. **Flatpak a11y bus:** read Flatpak's documentation of its accessibility-bus proxy policy (row 5.12 is Medium).
10. **Newton 2025–26 status:** whether the Wayland protocol was proposed to wayland-protocols, and whether GNOME 49/50 ship it (row 6.8).
11. **Android binder timeout** for node queries and the thread provider callbacks run on (row 7.11): measure with a deliberately slow provider.
12. **Windows text scale curve:** TextScaleFactor is "not … the same factor" for all text; measure the curve native controls use, so Izcal's CSS mapping matches.
13. **GNOME keys** (`text-scaling-factor`, `enable-animations`, `high-contrast`) and the portal version in which `contrast` and `reduced-motion` were added: check gsettings schemas and portal release notes.
