## 2. Algorithms, from published descriptions

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 2.1 | **Hunspell's model** (from its manual): a `.dic` word list with flags and an `.aff` affix file; PFX/SFX rules strip characters, add an affix and test a condition, with "twofold suffix stripping" and optional complex prefixes; compounding by flags and `COMPOUNDRULE` patterns; morphological fields; a personal dictionary file with forbidden words | — | [hunspell(5)](https://man.archlinux.org/man/hunspell.5.en) | read 2026-10-20 | High |
| 2.2 | Hunspell's suggestion sources: `REP` replacement patterns (highest priority) and `ph:` transliterations, `TRY` letter substitution in frequency order, `KEY` keyboard neighbours, `MAP` related characters, `PHONE` phonetic tables (from Aspell), n-gram similarity (`MAXNGRAMSUGS`, `MAXDIFF`), swaps and deletions; the manual gives no complete ordering beyond REP first | — | [hunspell(5)](https://man.archlinux.org/man/hunspell.5.en) | read 2026-10-20 | High |
| 2.3 | **Norvig (2007, updated 2016)**: choose c maximizing P(c)·P(w|c); a word of length n has 54n+25 edit-distance-1 candidates; 75% correct on a 270-word development set at 41 words/s, 68% on a 400-word test set at 35 words/s; failures from unknown words (5% and 11%), a crude error model, no context, mixed dialects | 54n+25; 68–75% | [norvig.com](https://norvig.com/spell-correct.html) | read 2026-10-20 | High |
| 2.4 | **SymSpell (symmetric delete)**: generates only deletes, turning the input's transposes, replaces and inserts into deletes of dictionary terms; "an average 5-letter word has about 3 million possible spelling errors within a maximum edit distance of 3, but SymSpell needs to generate only 25 deletes"; 0.033 ms per lookup at edit distance 2 and 0.180 ms at 3 (single core, 2012 laptop); prefix indexing cuts memory by "more than 90%"; licence changed from LGPL-3.0 to MIT in version 6.1 | 25 deletes; 0.033 ms | [SymSpell README](https://github.com/wolfgarbe/SymSpell) | read 2026-10-20 | High (README claims, not reproduced) |
| 2.5 | **Finite-state spellchecking** (Pirinen and Lindén, Helsinki; HFST): a weighted finite-state language model composed with a weighted error model; handles morphologically rich and compounding languages (Finnish, Sámi, Greenlandic) that word lists cannot enumerate | — | Pirinen & Lindén, "State-of-the-art in weighted finite-state spell-checking", CICLing 2014 (not fetched: PDF unreadable this session) | 2014 | Low |
| 2.6 | **GiellaLT/Divvun** build spellers, grammar checkers, hyphenators and keyboards for Sámi and other minority languages on "rule-based language technology" (lexc, twolc, HFST, Foma), distributed through Divvun Manager, MS Word and Google Docs; their online speller covers about thirty circumpolar languages | ~30 languages | [GiellaLT](https://giellalt.github.io/); [Divvun](https://divvun.org/) | read 2026-10-20 | High (scope); effort figures not found |

**Implications:** two families exist. Word-list-plus-affix models (Hunspell) suit English-like languages; finite-state morphology suits agglutinative and compounding languages, and is also a natural deterministic, integer-only representation (an automaton with integer weights). Suggestions are a ranking problem (error model × language model), where Norvig's own figures show the error model, not candidate generation, limits accuracy.

Spell-jacking shows that the risky part is not the algorithm but where the text goes, and that password fields need a rule that does not depend on the page setting `spellcheck="false"`.

## Implications for Izcal

1. Build one engine family: finite-state lexicons with integer weights (deterministic on every ISA, compact, good for morphology), with a word-list front end compiled into the same automaton form for simpler languages. Suggestion ranking is an error model × language model with integer scores.
2. Lexicons, affix or morphology rules, error models (keyboard adjacency, REP-style confusions, phonetic tables) and grammar rules are all language data authored by the language-data track; the spelling lexicon shares its stems with TX-D14's hyphenation lexicon.
3. No cloud, ever; no text sent to an OS provider whose privacy is unknown, unless the user chooses it.
4. Password, one-time-code and credential fields are never checked, whatever `spellcheck` says (spell-jacking, 4.1).
5. Results never reach script; `::spelling-error` styles are restricted to non-layout properties, and any future element-to-canvas API must exclude highlights.
6. Grammar: the scale is about 1,000–8,000 rules per language (3.6); English-only offline checkers exist (3.8). Ship per language behind a precision gate.
