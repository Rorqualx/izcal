# Izcal layout: specs_modern

Compiled 19 October 2026. Primary sources were preferred (CSSWG editor's drafts and /TR snapshots, the WHATWG HTML Standard, W3C/WICG drafts, CSSWG issue threads, vendor blogs and release notes, MDN browser-compat-data).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

**M-1 note:** no engine source code was read for this note (no code files, headers, commits, diffs, code reviews or source browsers). One search result pointed to a Chromium commit page; it was not opened and is not cited. One cited prose list (Paul Irish's "What forces layout" gist, 7.12) says its author built it by reading Blink source; it is used only as a list of hypotheses for black-box tests.

Method notes:
- Spec texts were downloaded on 19 October 2026 and read as text: CSS Containment 2 ED, CSS Containment 3 ED, CSS Conditional 5 ED (container queries; ED dated 8 October 2026), CSS Overflow 3 ED, CSS Scroll Anchoring 1 ED, CSS Scroll Snap 1 and 2 EDs, Scroll-driven Animations 1 ED, CSS Anchor Positioning 1 ED and the 27 March 2026 WD, CSS Sizing 4 ED, CSSOM View ED, Resize Observer ED, Intersection Observer ED and v2 draft, Layout Instability CG draft, LCP ED, MathML Core CR Snapshot of 24 June 2025, SVG 2 EDs (coords, embedded, text), and the WHATWG HTML multipage chapters (webappapis, rendering, urls-and-fetching, interaction, popover). Section names and step text below were checked in those files.
- **Ship versions** come from MDN browser-compat-data (BCD) JSON, main branch, fetched 19 October 2026 (data, not engine code). Release dates come from BCD's `browsers/*.json`. In BCD, "partial" means a partial implementation, and a version shown after "/" is an earlier partial or flagged entry. Each row links the MDN page that renders the same data.
- Two values were computed from spec files: the number of distinct `MATH.MathConstants.*` fields MathML Core reads (count of unique names in section 5.1), and the row count of the human-readable operator dictionary table (count of `<tr>` in appendix B.2, including headers).
- The search budget used was 7 web searches and 9 page fetches. Everything else was read from known primary URLs.

**Implications:** Izcal needs a *specified* style↔layout re-entry protocol for size queries, cq units and `@position-try`. The specs leave it undefined, so Izcal must write its own and test it against the from-scratch reference path (HGBA-3 B5). Proximity determination, the last remembered size and the scroll-state snapshot are frame-boundary state. They should be explicit, recorded inputs with fixed points in the frame pipeline (JS-D15), never side effects of whichever query happens to run.

**Implications:** Scroll anchoring, snap, scroll timelines and scroll-state queries all read layout output (scrollable overflow rectangles, snap areas) and feed scroll offsets back in. Izcal should compute the scrollable overflow rectangle once, as a first-class fragment field, and make every scroll-offset change a recorded input. A compositor that scrolls asynchronously needs only scroll-container geometry, snap areas and timeline ranges from layout. The suppression-window boundary has to be a defined, deterministic point in Izcal's frame, because the specs do not pin it.

**Implications:** Izcal should derive hit testing from the same stacking and paint-order structure it paints with, walked in reverse, with `pointer-events`, `inert`, clips and transforms applied. That makes "hit testing matches painting" true by construction, and testable against paint order. Where the specs are silent (3D, `foreignObject` under transforms, cross-process frames), Izcal's chosen behavior should be written down as an Izcal-defined rule, with WPT and black-box cases.

## Open questions and black-box measurements needed

1. **Style↔layout interleaving semantics** for container queries, cq units and `@position-try`: no spec defines them (1.7, 1.8). Black-box measure in Chrome 155, Firefox 158 and Safari 27: transitions on cq-unit changes, nested containers, a container that is also an anchor-positioned box (issue #11562 cases), and how many style passes a single frame can incur.
2. **`overflow-anchor` in Safari 27:** BCD says shipped. Confirm with a black-box test of the selection and suppression triggers (2.7–2.10) and compare against Chrome and Firefox. Note that the Apple release-notes text was not seen.
3. **Scrollable overflow interop:** the transform projection, margin areas of non-flex and non-grid children, and end padding (2.4, 2.5). WPT and black-box measurement needed per engine.
4. **The content-visibility proximity margin actually used** (spec suggests 50%), and the lazy-load scroll margin (implementation-defined, 4.6): black-box measurement needed per engine.
5. **Forced-layout list:** the gist (7.12) is Blink-derived. Each listed API needs a black-box test, for example by timing, or by observing ResizeObserver/IO state before and after, in all three engines. Separately, the CSSOM View/HTML hook for "update style and layout" for geometry getters is unspecified.
6. **Snapshot post-layout state:** CSSOM View §14 defines it, but HTML update the rendering does not call it as of 19 October 2026. Where do engines take the scroll-state snapshot relative to RO and IO? Black-box test with `scroll-state(stuck)` in Chrome.
7. **Layout Instability "pixels to significance" = 3** is stated only as Chrome's choice in a note. Do Firefox or Safari compute shifts at all? (`LayoutShift` is unsupported, 7.9.)
8. **MathML:** how engines measure ink ascent/descent (MathML Core issue 78), and whether any engine uses `MathKernInfo` despite Core not referencing it. Black-box test with fonts that have and lack kern info.
9. **Hit testing for 3D transforms and `foreignObject`** (8.4): no spec. Izcal must choose and document a rule. Black-box test the current Chrome/Firefox/Safari split.
10. **OOPIF geometry protocol:** what a parent renderer sends a cross-site child (size, viewport intersection, transform, throttling). The Chromium "oop-iframes-rendering" design document was not read. Find and read it as prose, or derive it from black-box behavior (IO in cross-origin iframes).
11. **`content-visibility: auto` in Safari:** BCD marks Safari 18 partial and Safari 26 full. What was partial? Black-box test relevance by focus or selection, and the event timing.
12. **Anchor-positioning spec churn:** the ED renamed values after the March 2026 WD. Track the WD → CR path before freezing Izcal's implementation targets.
