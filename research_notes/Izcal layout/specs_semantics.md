# Izcal layout: specs_semantics

Compiled 19 October 2026. Primary sources were preferred (papers, specifications, maintainers' posts, release notes, issue trackers).
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

**M-1 note:** no engine source code was read for this note. No code files, headers, commits, diffs, code review pages or source browsers of Blink, Gecko, WebKit, Servo, Ladybird, Taffy or any other engine were opened. Evidence is spec text, CSSWG minutes and issue text, vendor prose (WebKit blog, web.dev, Mozilla Hacks, release notes), Chrome Status entries (prose status data) and web-platform-tests (WPT) directory listings. Tests are not engine source.

**Method.** The current Editor's Drafts (EDs) of 21 CSS modules, three CSS 2.1 chapters and two HTML Standard chapters ("Tables" and "Rendering") were downloaded on 19 October 2026 and read as text. Maturity and dates come from each `w3.org/TR/<spec>/` "This version" URL, fetched the same day. CSSWG issue numbers come from the issue links inside each ED. Browser ship versions come from Chrome Status entries (Chrome only; the "Firefox/Safari view" fields there are often stale and were not used) and from vendor posts. **WPT counts** are file counts per `css/<dir>` in the `web-platform-tests/wpt` main branch on 19 October 2026, via the GitHub trees API. They exclude `support/`, `reference/`, `resources/`, `-ref.` files and non-HTML assets. They still include some references named otherwise, so treat them as ±20%. The shared web-search budget ran out part way through. Later items were checked against known primary pages, and items from recollection are graded Low.

**Implications:** Izcal cannot implement "the spec" for layout as one stable text. **Implications:** Box-tree construction needs inputs that are not plain CSS: HTML's element-specific display overrides (button, fieldset, legend, details shadow tree, replaced elements under `contents`) and quirks mode. Blockification belongs in the style system (it changes computed values and depends on the parent's display), so the style/layout interface must expose parent display to the computed-value pass. Anonymous boxes are a box-tree step and must be deterministic and counted in the 360 B layout budget.

## 7. Intrinsic sizing

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 7.1 | **Cyclic percentages** (Sizing 3 §5.2.1): when computing a box's intrinsic contribution, a percentage that resolves against the same axis is special. Non-replaced boxes treat the whole `width`/`max-width` expression (e.g. `calc(20px + 50%)`) as its initial value. Replaced boxes resolve it against **zero** for min-content (the "compressible" rule). Last remembered size is nondeterministic history and must be a recorded input under JS-D15.

## Open questions and black-box measurements needed

1. **Grid lanes property name.** Should Izcal ship `fit-tolerance` (ED) or `flow-tolerance` (Safari 26.4)? Watch #10884 and #12803 (orientation property) before freezing.
2. **Chrome and Firefox grid-lanes plans.** Chrome Status shows no shipping milestone and reads "No active development" (14 October 2026). Firefox's prototype uses old syntax. Not confirmed this session; check again before the layout spec freezes.
3. **Flex intrinsic sizing.** Black-box measurement: do Chrome, Firefox and Safari all match §9.9.1.2 exactly, including `flex-basis` interaction and multi-line min-content? Build a WPT-style matrix.
4. **Cyclic percentage behaviour.** Black-box measurement for replaced elements with `aspect-ratio` and percentage min sizes (Sizing 3 open question on transferred percentages).
5. **`text-wrap: pretty`.** The objective each engine uses is unpublished in spec text. WebKit's prose describes whole-paragraph evaluation; Chrome's is limited to the last lines. Measure line-break outputs on a corpus; define Izcal's own deterministic objective.
6. **`balance` limits.** The spec allows fallback above 10 lines. Measure each engine's actual line cap.
7. **Tables.** Auto layout width distribution and border-collapse resolution differ across engines (#604, #606, #608, #858). Black-box measurement of the three engines on the css-tables WPT plus a colspan/percentage corpus.
8. **Orthogonal flow multicol clause** (WM4 §7.3.2): does any engine create columns? Measure.
9. **Negative inset-modified containing blocks** (#11478): which engines follow CSS 2.1 and which follow Position 3?
10. **Ship versions graded Low** (Safari `margin-trim` 16.4; Firefox/Safari `text-wrap: balance`; anchor positioning in Safari/Firefox; `calc-size` outside Chrome; run-in absence; Compat 2021 and Interop 2022 lists). Re-check against release notes when search budget allows.
11. **WPT counts** are heuristic file counts. Re-count with the WPT manifest (tests vs references) before using them as budget figures.
12. **`display: contents` Appendix B** is non-normative. Check whether shipped engines agree on `button`, `legend` and `details` behaviour.
