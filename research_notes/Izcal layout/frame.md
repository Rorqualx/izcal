# Izcal layout: frame

Written 19 October 2026 (phase 1 of the first-principles-spec method).

## The problem and who has it

Izcal needs its own layout engine. HGBA-2 2.3.0 (M-1 part 1) excludes Taffy, Parley, Servo layout, Blitz, Yoga, Morphorm and every other library that does layout, so the Stage 1 design's "Taffy 0.15 algorithms behind the `hg-layout` driver" and "inline via Parley" (Section 5.6, M4) are void, and Stage 1's "Style and layout, 3–4 engineers" track, sized for adapters, is left holding a whole engine. The Phase 2 reconciliation records the layout spec as **the largest unowned item on Stage 1's critical path** (P23). The owner's direction (19 October 2026): engine work is all ours; generic infrastructure only; every shipped dependency and data set available under MIT; no shortcuts for time or complexity; staging only for correctness, security or measurement; cost is a planning fact.

Scope of this spec (layout from computed style and shaped text to the fragment tree that paint, hit testing, the semantic plane and script read):
- **Box tree**: box generation from the DOM and computed style (CSS Display 3/4, anonymous boxes, blockification, `display: contents`, pseudo-elements, list markers, form-control and other HTML-rendering-defined boxes, ruby), and how it is kept up to date.
- **Formatting contexts**: block (margin collapsing, BFCs), inline (line boxes, `vertical-align`, baselines, `text-box-trim`, initial letter, ruby; line breaking through the fonts and text spec's interface), floats and `shape-outside`, positioning (absolute, fixed, sticky, relative; static position; top layer), flexbox, grid (subgrid; masonry or "grid-lanes" status), tables, multicolumn.
- **Cross-cutting**: fragmentation (pages, columns, print), writing modes and orthogonal flows, bidi in layout, intrinsic sizing and percentage resolution, alignment and baselines, replaced elements and natural sizes, scroll containers and scrollable overflow, scroll anchoring, `content-visibility` and containment, container queries' layout side (scheduling the re-entry into style the style spec defines), anchor positioning, MathML Core layout, the SVG boundary (outer `<svg>` as replaced, `foreignObject`).
- **Engine architecture**: incremental layout and invalidation, the from-scratch reference path, parallel layout with phase purity, the fragment tree's representation and footprint, numeric representation, hit testing, geometry APIs (CSSOM View, ResizeObserver, IntersectionObserver, Layout Instability), and layout observability for DevTools and agents.

Not in scope: style (style spec), text shaping, fonts, Unicode algorithms and the line-breaking helper (fonts and text spec), paint, display lists, compositing and raster (future graphics spec, which consumes the fragment tree), animations (future animation spec), editing commands (future editing spec), SVG's own rendering and SVG text layout internals (future SVG spec; this spec owns the boundary), the print UI and PDF writer (shell and graphics). Interfaces to them are stated here.

Who has the problem:
- **People browsing**: pages must look right and stay still (layout shift), scroll and resize smoothly, print sensibly, and work at 400% zoom and in every writing system. Layout is a large share of main-thread time and of rendering crashes.
- **Web developers**: "why is this box this size?", "why did this wrap?", "why did this relayout?", "why did the page shift?", "why is there a scrollbar?", "why did this break onto the next page?". Mozilla's 2019 survey ranked layout debugging first "by far" of 23 design challenges (DevTools spec, row 19).
- **Izcal's engineers and agents**: layout must be deterministic (B1, DET-1, JS-D15), checkable against a from-scratch reference (B5, INC-1 to INC-4), parallel without changing results (HGBA-2 4.3: "a parallel layout path that changes output on any WPT test is disabled until fixed"), within FP-11's 360 B† per node for layout and paint, and memory-safe with no `unsafe`.

## What Izcal's specs already decide or constrain

- **HGBA-2 2.3.2**: P1–P6 precedence (P2 compatibility outranks P4 speed); **M-1** parts 1–4 (no engine libraries; MIT-only shipped code and data; spec anchors at pinned revisions; another engine's source code is never evidence; other engines are black-box differential signals only); I-1 (process per (site, container)); Section 4.3 (adaptive parallelism; parallel path bit-identical to sequential on WPT reftests; small documents sequential; HiPC 2016's 3.2× and 2.5× on 4 threads on some sites and no gain on others); C-1 WPT floors; ANC-1 anchor coverage.
- **HGBA-3**: B1 (deterministic substrate), B3 (fork/join phases with phase purity), B4 (data plane, restated by JS-D4), **B5** (layout as `layout(node, constraint_space) → immutable fragment`, cached by constraint space; ordered dirty queue (Spineless) and durability tiers as research; bulk fallback; demand-driven forced flush; "out-of-flow positioning, fragmentation, `:has()`, container queries and anchor positioning" need non-tree edges or a conservative fallback), **B6** (immutable fragment tree, flat inline item lists, property trees as data-oriented phase outputs), B7 (pixel-optional rendering: layout still runs), B8 (semantic plane reads fragments), DET-1 (fragment-tree hash in 1,000 of 1,000 replays), INC-1 (incremental beats from-scratch on ≥ 75% of frames, bit-identical), INC-2 (no frame class > 1.2×† slower), INC-3 (≤ 10%† metadata), INC-4 (fallback rate ≤ 50%† per context), FLUSH-1 (forced geometry queries ≥ 1.5×† faster than the Stage 1 baseline). Section 3: "The platform fixes synchronous layout".
- **Stage 1 design**: G1 (`hg-layout` reads only `hg-tree-traits`), G3 (determinism), G5 (`forbid(unsafe_code)` unless inventoried), G9 (anchors); 3.3 phase purity; 5.6 (driver API `layout(node, constraint_space) -> Arc<Fragment>`, fragments immutable; caching and from-scratch in Stage 1, Spineless queue in Stage B; tables written from CSS 2 and CSS Tables); 5.7 (paint produces property trees and paint chunks from fragments, CSS 2 Appendix E); 5.8 (semantic plane from fragments); M4 "layout and first pixels" and M6 (`ResizeObserver`, scrolling); 13.2 (printing and print-to-PDF are Stage 2 features; find in page Stage 1).
- **JavaScript engine spec 0.3 (accepted)**: **JS-D4** one-copy DOM (node columns outside the cage; workers read them only during a flush with the script thread blocked; never read the cage; never write the columns); **JS-D15** (every timing-dependent decision is a recorded B1 input); G6, G13–G18 (G18 checked arithmetic on untrusted sizes); release-by-ID slot reuse.
- **Resource-footprint spec 0.3 (accepted)**: FP-11 (DOM + style + layout + paint ≤ 512 B† per node; text and images excluded); FP-12 (class (a) stores discardable with bit-identical rebuild; "Layout fragments, inline item lists" are class (a)); FP-24 (canonical bytes deterministic); FP-2 (empty process ≤ 4 MiB†); FP-5; **FP-D16** (regenerable caches); 32-bit indices inside a process; generational handles across threads.
- **HTML and CSS parsing and style spec 0.3.2**: the **360 B†** layout+paint share of FP-11 (72 DOM + 80 style + 360); glyph runs charged to the text line, not to 360 B (P9); **container-query re-entry** `style_container_subtree(container, size)`, each container re-entered at most once per layout pass, scheduling owned by the layout spec; a reference block layout with size containment needed by ST-M2; the "affects" mask categories (style tells layout and paint what changed); demand-driven `getComputedStyle` for used values; scroll-state queries read the post-layout snapshot (a B1 input); the environment snapshot; crate layers L2s and L2p; the G-rule registry G19–G36 (this spec's rules start at **G37**); ST-D13 parallel styling with a deterministic merge; ST-D7 content-addressed style groups.
- **Fonts and text spec 0.3.3**: `hg-text` supplies shaped segments, break and justification opportunities, `break_reshapes`/`join_reshapes`/`kashida_point`, metrics, bidi maps, vertical text, the `MATH` table, `text-box-trim` edges, per-character bounds; **TX-D4** integer numeric contract (font size quantized in the drawing context's local space to the finer of 1/64 unit and 2⁻¹⁶ em; advances `round_half_even(value_fu × size_q / unitsPerEm)`; "the layout spec maps these values to its layout unit"); G28 (no floating point on observable paths in the text crates); TX-D16 partitioned, observationally transparent text caches, canonical-exempt (OD-4); the layout contract is fixed at TX-M0 (R22).
- **Networking spec 0.3.2**: lazy-loading fetches, image natural sizes arrive through decode; partition-keyed caches use the (T, C, X, n) projection (NW-D7). G30–G36.
- **DevTools spec 0.3**: T1 "why does this look or sit like this?"; DT-D3 why-queries under replay; DT-D4 spec-linked explanations (its "mapped" level for Taffy disappears); B5 incremental layout gates full layout why-queries; IIP's layout queries in `hg-inspect-renderer`.

## What success looks like (measurable)

Candidate target dimensions, to become LY- targets:
- **Correctness**: WPT `css/CSS2`, `css/css-display`, `css/css-flexbox`, `css/css-grid`, `css/css-tables`, `css/css-multicol`, `css/css-break`, `css/css-writing-modes`, `css/css-position`, `css/css-sizing`, `css/css-inline`, `css/css-align`, `css/css-contain`, `css/css-overflow`, `css/css-scroll-anchoring`, `css/css-anchor-position`, `css/css-page`, `mathml/`, `css/cssom-view`, `resize-observer`, `intersection-observer`, `layout-instability` pass rates against Izcal's own floors, with Interop focus areas at or above the best shipping engine.
- **Verification**: incremental equals from-scratch on every CI frame (fragment-tree bytes); parallel equals sequential; discard-and-rebuild identical; a spec-literal reference layout engine finds divergences.
- **Security**: no `unsafe` in layout; no recursion on content depth; every content-scaled loop under a fuel bound with spec-conformant overflow behaviour; no script runs during layout; fuzzing.
- **Performance**: full layout and incremental relayout time per corpus page and per Speedometer 3 workload relative to the best shipping engine; forced-flush latency; worst-case bounds on nested flex/grid; parallel gain with bit-identical output.
- **Memory**: layout + paint bytes per node within 360 B†; empty-process fixed cost.
- **Determinism**: DET-1 fragment-tree hash; cross-ISA identical geometry.
- **Visibility**: every box size explainable to its spec steps and inputs; every relayout attributable to its mutation; layout-shift attribution exact.
