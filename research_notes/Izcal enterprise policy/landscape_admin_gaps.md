# Izcal enterprise policy: today's landscape, admin pain points and the product areas to decide

Compiled 24 October 2026. Primary sources were preferred (vendor administrator documentation, vendor blogs, regulator guidance, standards). No third-party source code, header, commit, diff, code review or in-repository data file was opened or cited (M-1 part 3). Where a fact is stated only in code, this note says so and stops there.
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, a vendor claim without data, or a forum report; **Low** = secondary source only.

The session's shared web-search budget ran out partway through. After that, known primary pages were read directly. Claims that could not be checked are listed in Section 12.

## 1. Admin pain points

| # | Finding | Numbers | Source | Date | Conf. |
|---|---|---|---|---|---|
| 1.1 | **Silent precedence.** In Chrome, if the same policy comes from more than one source, "the policy at top of the hierarchy is applied, and all other policies are ignored." The default order is platform (GPO/MDM), then machine cloud, then OS user, then cloud user. Admins change the order with `CloudPolicyOverridesPlatformPolicy` and `CloudUserPolicyOverridesCloudMachinePolicy`. | 1.2 | **Edge has the same model, with different defaults and a private override.** Policy from the Edge management service "will be overridden if they conflict with an existing Group Policy Object (GPO) or Mobile Device Management (MDM) policy." To reverse that, admins set `EdgeManagementPolicyOverridesPlatformPolicy`, which is "a private policy and must be set via the registry". Device policy beats user policy unless `EdgeManagementUserPolicyOverridesCloudMachinePolicy` is set. **Implications:** The recurring pain is not missing policies. It is silent non-application: precedence, device-state gating, profile type and template skew, each visible only as "Ignored" or "Error" on an internal page. Izcal can make every ignored or overridden value explainable: which source set it, which rule dropped it, and what to do about it. It can also make one policy name mean the same thing on every OS.

**Implications:** Izcal cannot implement an open delivery standard, because none exists. The schema decision is whether to accept Chromium-shaped policy names and JSON shapes as an interoperability vocabulary, since admins already script against them.

It needs a black-box specification (by observing a real agent's traffic) or a published prose specification from a vendor. That is a real, unresolved gap.
