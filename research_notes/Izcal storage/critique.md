# Izcal storage: independent design critique (phase 8)

Reviewed 20–21 October 2026. Subject: `reports/Izcal storage.md`, draft 0.1 (20 October 2026). Reviewed against: HGBA-2 (`reports/HGBA 2 browser architecture spec.md`, rev 2.1.3), Stage 1 design (`reports/HGBA Stage 1 architecture design.md`), DOM spec 0.2.1 (`reports/Izcal DOM, bindings and event loop.md`), resource footprint 0.4.1 (`reports/Izcal resource footprint.md`), networking 0.3.4 (`reports/Izcal networking.md`), DevTools 0.3 (`reports/Izcal DevTools spec.md`), ST-D17 (parsing and style 0.3.3), MD-31 (images and media 0.4), CB 6.5 (content blocking 0.3), and `research_notes/Phase 3 amendments/ledger.md` (G-19, C-5 registry). The spec's own research notes (`research_notes/Izcal storage/*.md`) were read where a claim's provenance mattered.

Verified clean (no finding): the prefix statement (**SG-** collides with nothing; G150–G159 is free — the ranges G100–G149 and G160–G179 are taken by the batch-2/3 specs, G150–G159 is not); every amendment quote in Section 9.5 was checked verbatim against the current text of its target (HGBA-2 4.6 sentence, HGBA-2 Section 3 diagram line, Stage 1 Section 1 Storage row, Stage 1 13.2 Storage and Everyday-features rows, NW 6.9 + NW architecture diagram, DOM 6.13/6.18, FP 8.2/9.4, DT "storage keys" view) — all accurate; the SQLite/WAL sweep of `reports/` finds no stale mention the 9.5 table misses (NW-D11's option (b) names SQLite only as a rejected alternative, which is decision history, not stale text); no engine source code is cited anywhere in the spec or notes (the note's GitHub links are to prose docs, READMEs and licence files, which M-1 part 3 permits); contract adherence is real on DM-D11's snapshot protocol (6.7 matches DM 6.13 step for step, including task-boundary installs as recorded inputs and the 5 MiB window bound), DM-D12 opaque clone-wire values (G152's forever-decoder), MD-31 opaque responses never delivered to a renderer, FP-D18's 24 h/7 d/private-window rules, DT 6.5's scoped principals and rule-10 bundle handling, NW's (T, C, X) + O storage key vs the (T, C, X, n) renderer projection (6.8 restates the distinction correctly), the no-sync-IPC position (G156, consistent with DM 9.5 and NW 9.5), sessionStorage/Web Locks confirmations, and cookie-jar persistence per NW 6.9. SG-D1's rejection of SQLite on the MIT-only rule is the correct strict reading.

| C-01 | **High** | Internal contradiction between rule G153 and the design. G153: "no plaintext page is ever placed in a mapped region". Section 6.7 maps plaintext snapshot-window pages read-only into renderers (necessarily — the renderer holds no keys), and states the windows' pages are "clean, file-backed". Both cannot hold with AEAD-at-rest: if the window file on disk is AEAD-encrypted, its pages cannot be mapped as plaintext (the mapper would read ciphertext); if a decrypted copy is mapped, it is anonymous shared memory, not "clean, file-backed". ## MUST-FIX before 0.2

1. **C-M1 (C-01)** — Resolve the G153 / Section 6.7 / SG-9 contradiction: state the snapshot-window mechanism (encrypted at rest vs the plaintext mapped image the renderer needs), who allocates the mapped region, and reword G153 or carve the named exception. As written, a normative rule of the spec and its central design section contradict each other.
2. **C-M2 (C-02)** — Add the Stage 1 Section 2 amendment row: layer placement for every `hg-store-*` crate, registration of G150–G159 in the C-5 registry, and an explicit reconciliation of G150 with G3's letter (or a rewording of G150 that needs no G3 change). Without it, a crate rule of this spec contradicts an accepted Stage 1 rule with no amendment row to cover it.
3. **C-M3 (C-03)** — Make the three deferred reversal triggers measurable: declare SG-D3's power bound, SG-D5's threshold (tie it to PRIV-2's actual (a) threshold, and note the dependency on the proposed amendment), and SG-D6's prompt floor — or name the milestone and owner that sets each.
4. **C-M4 (C-04)** — Fix the staffing arithmetic (7–10 people over 48–60 months cannot be 60–95 engineer-years).
5. **C-M5 (C-05)** — Name the scratch-shelf host process and resolve the fresh-shelf vs recorded-values-read tension in 6.12/SG-D8.
6. **C-M6 (C-06)** — Add the explicit P1 reconciliation for one per-profile storage service holding all partitions, and put the in-service cross-partition-corruption residual into the threat-model hand-off.
7. **C-M7 (C-07)** — Repoint SG-D10's reversal trigger from FP-11 (per-node DOM/style/layout/paint bytes) to the budget that actually measures renderer blob backing, or propose the FP amendment that creates one.
8. **C-M8 (C-08)** — Correct "five places" to six, and align the engine-design note's SQLite licence-register row with the spec's strict MIT-only reading.

Recommended but not blocking: C-09 through C-19.
