# Izcal devices: API specifications and underlying standards

Compiled 21 October 2026. Primary sources were preferred (specifications, standards bodies, maintainers' issue trackers). Every row is anchored to published prose read in its own text; no third-party source code, header, commit, diff or review was read or cited (M-1 part 3). The six API documents were retrieved and read on 21 October 2026 as plain-text conversions of the served pages; quotes and IDL are from those copies.

Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, or a vendor claim without data; **Low** = secondary source only.

Izcal builds its own device-access stack from the specifications' prose (M-1). Where a document leaves behaviour to the user agent (chooser UI, permission storage, blocklist fetching, OS driver calls), that is Izcal design space, not a fact to copy from another browser.

**Method notes and access limits.** Four documents that began as WICG drafts are now served from `*.spec.whatwg.org`; they remain Community Group reports, not WHATWG standards, and this note records the hosting move rather than treating it as a change of standards body. Web NFC's `w3.org/TR/web-nfc/` URL returns 404 and the current Community Group URL serves a document with no status or date block. ISO/IEC 18092 and the NFC Forum NDEF text could not be read directly (paywall and login wall), so the NDEF/TNF model below comes from Web NFC's own normative prose and the ISO edition is flagged unknown. The USB 3.2 PDF was not retrieved; USB 2.0 and WebUSB's own BOS descriptor text are used. MIDI 2.0/UMP was searched for in the Web MIDI Working Draft and is absent; the separate MIDI 2.0 documents were confirmed on MIDI.org but not read in full.

| # | Finding | Numbers | Source | Date | Conf. |

**Implications:** Izcal needs one permission broker with per-API descriptors, but cannot assume a uniform model: HID and Serial have no `navigator.permissions.query()` story, NFC's prompt is undefined, and MIDI may be implicitly granted. The broker must own persisted grants keyed by origin plus device identity, expose a chooser only where the spec requires one, and treat `usb-unrestricted` as an Isolated-Web-App-only capability rather than a normal grant.
