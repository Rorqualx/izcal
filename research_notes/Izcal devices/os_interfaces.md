# Izcal devices: OS interfaces

Compiled 21 October 2026. Primary sources were preferred (vendor documentation, kernel documentation, man pages and standards).

M-1 note: this note uses only published prose, vendor documentation, man pages and standards. No third-party project's source code, headers, commits, diffs or code reviews were opened. Where a library is named (libusb, libnfc, pcsc-lite) its behaviour is taken from its published documentation; the library itself is not used or linked. A specification or API reference describes a contract; it is not a template to copy from an implementation.

Confidence: **High** = the primary documentation text was read and the claim checked in it; **Medium** = an official page's summary, a secondary source, or a claim inferred from an authoritative list; **Low** = secondary source only; **Gap** = no published evidence found; **Inference** = my conclusion from the cited rows, not a published statement. Absence of a documented API is evidence for "not exposed", not proof that no private route exists.

**Method notes.**
- Scope: what macOS, Windows, Linux and Android expose to a user-mode process for USB, HID, serial, MIDI, Bluetooth and NFC, under which permissions and sandboxes, and what that implies for where each web device API's stack can live. It does not decide the web API surface; it records the OS cost of each choice.
- Apple documentation was read through its published markdown/JSON alternates (`developer.apple.com/tutorials/data/documentation/...md`), which carry the same text as the rendered page. Microsoft Learn, kernel documentation, man pages and Android developer documentation were read directly.
- The shared search budget was used for the gaps the brief identified (BlueZ policy, Linux HCI privilege, neard status, Windows MIDI 2.0, Android MIDI and NFC). About a dozen searches were made; later items were direct fetches of known primary URLs. Rows not re-read at the source after a failed fetch are graded Medium or Low.
- Browser-support rows use caniuse's tables read on 21 October 2026. They record a point in time, not a commitment.
- Dates are the source's publication or update date where shown; otherwise "read 2026-10-21" means the page was read that day and carries no date.

**Implications:** Izcal must plan four OS backends per device class, not one. The renderer never touches a device handle: a broker-owned service holds the OS handle, applies the site grant, and forwards only the reports or bytes the API allows. NFC is an Android capability plus, at most, a desktop extension built on PC/SC readers; it cannot be promised as a cross-desktop web API.
