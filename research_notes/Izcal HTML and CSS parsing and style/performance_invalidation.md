# Izcal HTML and CSS parsing and style: performance and invalidation

Compiled 19 October 2026. Primary sources were preferred (papers, maintainers' posts, bug trackers, engine team blogs, HTTP Archive). Engine source code read at phase 2 was removed as evidence at 0.3.1.
Confidence: **High** = primary source read and the claim checked in its text; **Medium** = primary abstract or snippet, a source comment without published data, or a vendor claim without data; **Low** = secondary source only, or recalled and not re-read this session.

**Provenance note (updated 0.3.1, 19 October 2026).** HGBA-2 2.3.1 M-1 part 3: another engine's source code (code files, headers, commits, diffs, code reviews) is never evidence. At phase 8 the rows read from engine source files were only marked; in the 0.3.1 source-evidence pass they were **replaced** by published prose (documentation, bug-tracker discussion, blogs, papers, mailing lists), **turned into black-box measurements** planned at ST-M0, or **removed**. The per-row log is [source_evidence_pass.md](source_evidence_pass.md). Prose design documents hosted in a repository (for example a `docs/*.md` page or a README) remain usable; commit messages and code reviews do not.

**Method note (M-1).** This strand follows phases 2 and 3 of `.claude/skills/first-principles-spec/SKILL.md` for the frame in `frame.md`. It records **ideas and measured evidence only**: no code, data structure layout or template is taken from any engine (HGBA-2 M-1, Stage 1 D-S10). At 0.3.1 every row that rested on engine source files was replaced, turned into a black-box measurement or removed (provenance note above). Engine blog figures are vendor measurements on vendor benchmarks; they show direction and size, not independent results. The shared web-search budget ran out partway through this strand; after that, known primary pages were fetched directly, and items that could not be checked are graded Medium or Low and listed in Section 13. Facts already recorded elsewhere are cited, not repeated: node sizes, attribute sharing, Stylo's sharing cache size and Blink's `ComputedStyle` base size are in [`compact_engine_data.md`](../Izcal%20resource%20footprint/compact_engine_data.md) Sections 1, 2 and 4; Speedometer 3 governance and the "Speedometer is mostly not a JS benchmark" finding are in [`execution_performance.md`](../Izcal%20JavaScript%20engine/execution_performance.md) Section 2; Spineless Traversal is in [`incremental_computation.md`](../Future%20software%20browser%20engine/incremental_computation.md).

**Implications:** The evidence moved from "selector matching dominates loads" (2009) to "parsing is on the load critical path and style recalc dominates some interactions" (2013–2023). Izcal's targets need **both** a load metric (parse throughput, first-byte-to-first-node) and an **interaction metric** (incremental restyle time per mutation on large-rule-count apps such as the 10k–28k-rule set in 1.5). Like the JS engine (execution_performance 1.6), Izcal must build its own per-phase time accounting, because nobody publishes a current split.

Lookup depth through shared sets must be bounded (first principles: a lookup walks the chain); Izcal derives its own structure and bound.

## 13. Gaps, flagged claims and unchecked items

- **Search budget.** The shared web-search budget was exhausted mid-strand.
