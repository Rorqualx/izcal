# What Izcal can do that other browsers cannot

Starting points for "what could we expose that no one does". Each item names the spec that defines it; read that section before relying on it, because the specs are the source of truth and may have changed since this list was written (17 October 2026).

| Capability | What it makes possible for tools | Where it is defined |
|---|---|---|
| **Deterministic runtime substrate.** The engine can run in simulation mode, with recorded inputs, a seeded scheduler and a virtual clock; V8 is deterministic under the fork's predictable platform, with identical hashes on macOS, Linux and Windows | Record a session and replay it exactly: time-travel debugging, bug reports that reproduce, bisecting a recording, comparing two runs step by step | HGBA-3 B1, DET-1; Stage 1 design Section 3; `m0/determinism_crossplatform.md` |
| **Typed capability channels.** All cross-process communication goes through typed, generated IPC with a simulation transport | Inspect every message between processes, with fault injection; show process and site-isolation boundaries as they are, not inferred | HGBA-3 B2; Stage 1 design Section 4 |
| **Data plane and mutation log.** DOM changes are logged and applied to a Rust data plane at each style and layout flush | Show exactly which mutation caused which restyle or relayout, and replay mutations | HGBA-2 Section 6 (F1); HGBA-3 B4; Stage 1 design Section 5.4 |
| **Incremental core with a from-scratch reference path.** Every incremental result can be checked against a from-scratch computation | Explain invalidation ("why did this recompute"), and verify that what is shown is correct | HGBA-3 B5, INC targets; Stage 1 design Section 5.6 |
| **Semantic plane.** The accessibility tree is a first-class pipeline output with stable node IDs, plus a repair overlay | An accessibility view that shows the author tree, the repaired tree and how they differ, with spec references (HTML-AAM, accname) | HGBA-3 B8; Stage 1 design Section 5.8 |
| **Agent principal and origin capabilities.** Agents act as a distinct principal with origin-scoped capabilities and a tool registry, and AI is off by default | A safe channel for AI agents to use the developer tools, with consent and audit | HGBA-3 B9, B10; AG targets |
| **Spec anchors.** Engine algorithms carry `// spec:` anchors to the specification sections they implement, and an anchor index joins them to WPT tests | Tools can link any behavior to the exact specification step and its tests: "this is the step of the spec that did this" | HGBA-2 M-1, ANC-1; Stage 1 design G9, `hg-anchor` |
| **Engine renders its own UI.** The shell, and under D-S11 the DevTools frontend (`hg-devtools`), are HTML applications rendered by Izcal | Developer tools can live anywhere the engine draws: overlays, full workspaces, separate windows, not only a docked panel | Stage 1 design D-S2, D-S11 |
| **Own network stack.** A network service in its own process, with rustls, neqo for HTTP/3, and (site, container) partitioning | Protocol-level visibility (TLS, QUIC, partitioning keys) from code Izcal owns | HGBA-2 Section 4.7, I-1; Stage 1 design Section 6 and 13.2 |
